## 2. UI 친화도 재순위

### 2.1 평가 기준 — seminar.pi 조건에 맞춘 5개

seminar.pi 사용자는 **Pi Browser(모바일 WebView, 앱 설치 불가)** 안에서 입장한다. 그래서 "데스크톱 앱이 예쁜가"가 아니라 아래 5개로 본다.

| # | 기준 | 왜 |
|---|---|---|
| K1 | 설치 없이 웹에서 완전한 기능 | Pi Browser 는 별도 앱을 깔 수 없다 |
| K2 | 첫 입장까지 단계 수 | 세미나 참가자는 처음 오는 사람이 대부분 |
| K3 | 모바일 하단 컨트롤 수(적을수록 좋음) | 좁은 세로 화면 |
| K4 | 학습 부담(메뉴 깊이·숨은 기능) | 비전문 커뮤니티 사용자 |
| K5 | G2 Ease of Use(참고) | 외부 사용자 평가. Teams 쉬움 4위·Zoom 6위(점수 9.1), **Google Meet 은 이번 검색에서 데이터 없음** — 참고만 |

### 2.2 점수 (5점 만점, 서비스 판정)

| 앱 | K1 웹 완결 | K2 입장 단계 | K3 컨트롤 수 | K4 학습 부담 | 합계 | 순위 |
|---|---|---|---|---|---|---|
| **Google Meet** | 5 — 처음부터 브라우저 전용 설계 | 5 — 링크 → 대기실 1화면 → 입장 | 5 — 하단 바 5~6개 | 5 — 기능 대부분이 바에 바로 보임 | **20** | **1** |
| Zoom | 3 — 웹 클라이언트는 기능 축소, 앱 설치 유도 | 3 — 앱 열기 안내 화면을 거침 | 3 — 바 8~9개 + 더보기 | 3 — 설정 많음, 웨비나 모드는 우수 | 12 | 2 |
| Microsoft Teams | 3 — 웹판 있음, 조직 계정 전제 | 2 — 계정·테넌트 선택 | 3 | 2 — 채팅·팀·채널 등 회의 밖 기능이 섞임 | 10 | 공동 3 |
| Cisco Webex | 3 — 웹 앱 있음, 기업 계정 중심 | 2 — 회의 번호·계정 단계 | 3 | 2 — 기업용 설정 많음 | 10 | 공동 3 |
| GoTo Meeting | 2 — 앱 설치 중심 | 2 | 3 | 3 — 회의 기능만이라 단순 | 10 | 5 |

동점(10점)은 K1(웹 완결)을 우선해 GoTo 를 5위로 두고, K1·K4 까지 같은 Teams·Webex 는 공동 3위다. K5 는 Meet 자료가 없어 합계에서 뺐다. 점수는 공개 사용 경험에 근거한 서비스 판정이다(실측 아님).

**판정 : 1위 Google Meet.** 근거는 ① 설치 없는 웹 입장이 기본 경로이고 ② 대기실 한 화면에서 카메라·마이크를 점검한 뒤 들어가며 ③ 하단 바 하나에 핵심 기능이 다 있어 숨은 메뉴가 거의 없다는 점이다. 셋 다 Pi Browser 조건과 그대로 맞는다.

**보완 : Zoom Webinar.** Meet 은 "모두가 참가자"인 회의형이다. seminar.pi 는 발표자 1명(또는 패널 몇 명)이 청중 다수에게 보내는 **웨비나형**이므로, 청중은 기본 비발행·발표자 고정·손들기·질문(Q&A) 같은 웨비나 기능을 Zoom Webinar 방식으로 보탠다.

출처 : [G2 무료 화상회의 소프트웨어](https://www.g2.com/categories/video-conferencing/free) · [G2 Zoom 비교](https://www.g2.com/compare/freeconference-com-vs-zoom-workplace)

## 3. 1위 Google Meet — UI·핵심 기능 분석

> 아래 동작 설명은 서비스가 알고 있는 Google Meet 웹 화면 기준이다. 버튼 구성·단축키·자동 숨김 동작은 Google 이 수시로 바꾸므로 **[확인중 : 서비스 — Google Meet 고객센터 대조]**. 설계 결정은 이 표의 "왜 쉬운가"(원리)에 근거하므로 세부가 달라도 적용 설계는 유효하다.

| # | 요소 | 동작 | 왜 쉬운가 | seminar.pi 적용 |
|---|---|---|---|---|
| G1 | **대기실(green room)** | 입장 전 내 카메라 미리보기, 마이크·카메라 켜고 끄기, 이름 확인, "지금 참여" 큰 버튼 | 들어가기 전에 "내 모습·소리"를 확인해 불안이 없다 | 그대로 — **Pi Browser 자동재생 정책 해결에도 쓴다**(입장 버튼 탭 = 사용자 제스처 → 이후 `video.play()` 성공) |
| G2 | **무대(stage)** | 화면 대부분이 영상. 발표 중이면 발표 화면 크게 + 나머지 작게 | 볼 것이 하나라 시선이 흩어지지 않음 | 발표자 고정(spotlight) 기본 |
| G3 | **하단 컨트롤 바** | 가운데에 마이크·카메라·손들기·반응·화면공유·더보기·빨간 나가기 | 모든 핵심 기능이 엄지 닿는 한 줄 | 역할별로 버튼 수를 줄여 4~5개(6.1) |
| G4 | **토글 상태 색** | 꺼진 마이크·카메라는 빨간 원 버튼 | 상태를 색 하나로 즉시 인지 | 꺼짐 = danger 색 채움(9절 토큰) |
| G5 | **사이드 패널** | 오른쪽 아래 채팅·참가자·활동 아이콘 → 오른쪽 패널(모바일은 전체 화면 시트) | 무대를 가리지 않고 필요할 때만 | 같은 구조, 모바일은 하단 시트 |
| G6 | **자동 숨김** | 몇 초 무조작이면 바가 사라지고 화면 탭으로 복귀 | 영상 면적 최대 | 데스크톱 4초 무조작 숨김(포인터가 바 위·메뉴 열림이면 유지), **모바일은 타이머 없이 탭 토글** — 14.3 Jitsi 근거 |
| G7 | **말하는 사람 표시** | 타일 테두리·음성 막대 | 누가 말하는지 바로 앎 | 오디오 레벨로 타일 링 표시(클라이언트 `AudioContext` 측정, 서버 변경 없음) |
| G8 | **손들기·반응** | 손들기는 참가자 목록 상단 정렬 + 알림, 이모지 반응은 화면에 떠오름 | 말 끊지 않고 의사 표시 | 웨비나에서 더 중요 — 7.2 신규 메시지 |
| G9 | **단축키** | `Ctrl+D` 마이크, `Ctrl+E` 카메라 | 데스크톱 고급 사용자 속도 | 데스크톱만 같은 키 지원 |
| G10 | **연결 품질 안내** | 네트워크 불안정 시 상단 토스트 | 화질 저하 이유를 알려 줌 | 엔진 `score`(M4) 알림을 받으면 표시 |

## 4. 차용 원칙

1. **패턴만 차용한다.** 화면 흐름(대기실 → 무대 → 하단 바)과 배치는 업계 공통 관례라 따른다.
2. **Google 상표·로고·고유 색 조합·아이콘 세트는 복제하지 않는다**(트레이드 드레스 위험 + 등재 심사 "독립 완성도"). 색은 seminar.pi 기존 다크 토큰에서 확장(9절), 아이콘은 오픈 라이선스 세트를 쓴다 [TBD : 아이콘 세트 — 현재 의존성 없음, 인라인 SVG 로 시작].
3. **Pi 결제·로그인 흐름이 우선한다.** 외부 앱의 패턴이 핵심 가치(Pi Browser 로그인·결제·입장)와 부딪히면 패턴을 버린다.

## 5. seminar.pi 화면 5종

PRD 6절 초안(목록·상세·화상 룸·개최·내 세미나)을 아래로 확정 제안한다. 내 세미나는 목록의 탭으로 합쳐 화면 수를 줄인다.

| # | 화면 | 경로(제안) | 핵심 | PRD |
|---|---|---|---|---|
| S1 | 목록 | `/[locale]` (홈) | 예정·진행 중 세미나 카드, **서버 페이지네이션**(데이터 패칭 표준 ①), 탭 : 전체·내가 연 것·내가 참가한 것 | F-03 |
| S2 | 상세 | `/[locale]/s/[id]` | 제목·일시·개최자·정원·입장료, 버튼 1개(무료 = "입장", 유료 = "Pi 로 결제하고 입장") | F-03·F-04 |
| S3 | **대기실** | `/[locale]/s/[id]/join` | G1 — 미리보기·토글·이름·입장 | F-05 |
| S4 | **룸** | 같은 경로, 입장 후 상태 전환(페이지 이동 없음) | G2~G10 | F-05 |
| S5 | 개최 | `/[locale]/host/new` | 제목·일시·정원·입장료 입력 | F-02 |

> S3 → S4 를 **같은 페이지의 상태 전환**으로 두는 이유 : 대기실에서 얻은 카메라 스트림·사용자 제스처를 그대로 룸에 넘긴다. 페이지를 이동하면 스트림이 끊기고 Pi Browser 에서 자동재생이 다시 막힌다.

### 5.1 대기실 (S3) — 모바일 세로

```

│ ← 세미나 제목                  │
```

## 6. 룸 상세 설계

### 6.1 역할별 하단 컨트롤

엔진 역할 3종(`presenter`·`panel`·`audience`, SIGNAL_API 6절 `role`)에 맞춘다.
현재 입장권 API(`src/app/api/media/ticket/route.ts`)는 `cap: present|watch` 로 **presenter(관리자만)·audience 2종만** 발급한다 — panel 발급 경로와 개최자의 presenter 권한(F-02)은 [TBD : 13절 #8]. 그 전까지 panel 열은 설계만 둔다.

| 버튼 | presenter | panel | audience | 동작 |
|---|---|---|---|---|
| 마이크 | ● | ● | — | 켜기/끄기 토글 |
| 카메라 | ● | ● | — | 켜기/끄기 토글 |
| 화면공유 | ●* | ●* | — | 화면 트랙 발행(`source: screen`) |
| 손들기 | — | — | ● | 토글, 발표자 참가자 목록 상단에 정렬 |
| 반응 | — | ● | ● | 이모지 7종(14.4, 13절 #4 결정) |
| 채팅·참가자 | ● | ● | ● | 사이드 패널(모바일 하단 시트) |
| 나가기 | ● (빨강) | ● | ● | `leave`. 발표자는 [나가기]/[세미나 종료] 선택 대화상자 — 종료는 `room.end`(13절 #6) |

\* **화면공유는 기능 탐지로 노출**한다 : `navigator.mediaDevices?.getDisplayMedia` 가 없으면 버튼을 숨긴다. 모바일 WebView 는 대부분 없다. **UA 로 판정하지 않는다**(루트 CLAUDE.md UA 불신 철칙과 같은 원칙).

### 7.1 기존 메시지로 되는 것 (SIGNAL_API v1.0 — 엔진 변경 없음)

### 7.2 신규 필요 — SIGNAL_API v1.1 (채택 : 13절 #1 결정, 엔진 구현 전까지 해당 UI 숨김)

SIGNAL_API 머리말 규칙("이름·필드 변경은 M3 합의 필요")에 따라 **제안만** 적는다. 합의 전에는 해당 UI(인원 수·이름·참가자 패널·화면공유 레이아웃·채팅·손들기·반응)를 숨긴다.

**① 참가자 목록** — 현재 `join` 응답 `producers` 는 `{id, kind, peer}` 뿐이고 `consumerCreated` 에 이름이 없으며 입장·퇴장 알림도 없다(`envelope.go`).

| 메시지 | 방향 | `d` | 받는 사람 | 용도 |
|---|---|---|---|---|
| `join` 응답 필드 추가 | S→C | `peers: [{peerId, name, role}]` | 입장자 | 대기·입장 직후 참가자 목록·인원 수 |
| `peerJoined` (ntf) | S→C | `{peerId, name, role}` | 방 전원(본인 제외) | 목록 추가 |
| `peerLeft` (ntf) | S→C | `{peerId}` | 방 전원 | 목록 제거 |

청중 30명이 몰려 들어올 때 알림 폭주를 막으려면 `peerJoined` 도 reaction 처럼 묶음 전송을 검토한다(R-P2).

**② producer 출처** — `ProducerInfo`·`ConsumerCreated` 에 `source`(`camera`|`screen`|`mic`) 필드 추가. 필드 추가는 하위 호환(SIGNAL_API 9절).

**③ 채팅·손들기·반응**

| 메시지 | 방향 | `d` | 받는 사람 | 용도 |
|---|---|---|---|---|
| `chat.send` (req) | C→S | `{text}` (최대 500자) | — | 채팅 보내기. 서버가 길이·속도 제한(`RATE_LIMITED`) |
| `chat` (ntf) | S→C | `{peerId, name, text, ts}` | 방 전원 | 채팅 받기 |
| `hand.set` (req) | C→S | `{raised: boolean}` | — | 손들기/내리기 |
| `hand` (ntf) | S→C | `{peerId, raisedTs}` (0 = 내림, 서버 시각) | presenter·panel(+본인) | 손 든 목록 갱신 — 이름은 `peers` 목록에서 조인 |
| `hand.lowerAll` (req) | C→S | `{}` | — | presenter 만, 권한 검사는 서버 |
| `reaction.send` (req) | C→S | `{emojis: string[]}` (허용 목록만, 최대 3) | — | 반응 — 클라이언트 500ms 묶음 |
| `reaction` (ntf) | S→C | `{counts: {[emoji]: n}, ts}` | 방 전원 | 클라이언트 500ms 묶음 송신 + **서버 300ms 창 합산·익명** 방송(청중 30명 폭주 방지, R-P2) — 14.4 |

- 채팅 저장 : **저장 안 함 — 엔진은 중계만**(13절 #2 결정, DB 부하 0·개인정보 최소).
- WebRTC DataChannel 대신 기존 WebSocket 을 쓰는 이유 : 이미 열려 있고 순서·인증(입장권)이 보장된다.

훅 반환 형태(초안) :

```ts
type RoomState = 'idle' | 'ticket' | 'connecting' | 'joined' | 'reconnecting' | 'closed' | 'error'
type Peer = { peerId: string; name: string; role: 'presenter' | 'panel' | 'audience'; hand?: boolean }
type Track = { producerId: string; peerId: string; kind: 'audio' | 'video'; source: 'camera' | 'screen' | 'mic'; paused: boolean; stream: MediaStream }

useRoom(roomId) => {
  state, error, role, peers, tracks,
  join(localStream?), leave(),
  setMic(on), setCam(on), shareScreen(on),
  setLayer(consumerId, maxSpatial),
}
```

### 14.7 시그널링 v1.1 제안 — 7.2 를 대체하는 통합본

명명은 기존 규약(요청 = `대상.동사`, 알림 = camelCase), 실패는 기존 봉투 `e{code,msg}`·기존 코드(`ROLE_FORBIDDEN` 등) + 신규 `LOCKED` 1개(SIGNAL_API 5절 표 '연결' 열 = 유지, `envelope.go` `ErrCode` 추가 대상).

- 메시지 수 : 현재 요청 12·알림 10 → 필수 A~D 반영 시 요청 17·알림 16, 후속 E~G 까지 요청 21. SIGNAL_API D-9 의 되돌릴 조건(메시지 20개 초과 시 JSON Schema 전환 검토)에 **후속 E 착수 시점**에 닿는다 — 그때 전환 판단 [확인중 : 마스터].

### 15.2 하단 바 — 버튼 수 불변

- **새 기능은 메인 슬롯을 차지하지 않는다.** `barOrder`·`mainSlots`(room-rules, 14.3 표)는 바꾸지 않는다.
- **불변의 기준** = 14.3 표의 상한 **'메인 슬롯 + 1칸 + 나가기'** 다. v1 에서 '+1칸'은 ⋯ 이거나 넘친 버튼 1개였다. 부가 항목이 1개라도 있으면 그 자리는 늘 ⋯ 이다. 이때 '넘친 것이 1개면 바로 노출' 규칙은 쓰지 않고, 넘친 버튼도 ⋯ 안으로 들어간다. 부가 기능이 몇 개로 늘어도 칸 수는 이 상한을 넘지 않는다.
  - 구현 1줄 : `splitSlots(items, slots, extra)` — `extra` 가 비면 지금과 같고, 아니면 `main = items.slice(0, slots)`, `more = [...items.slice(slots), ...extra]`.
  - 시험 : 역할 3종 × 폭 4구간에서 `main + (more ? 1 : 0) ≤ slots + 1` 을 확인한다(node:test, `room-rules.test.mjs`).
- **⋯ 메뉴 순서** : 넘친 기본 버튼(14.3 순서) → 구분선(`role="separator"`) → 부가 항목.

| 역할 | 부가 항목(위 → 아래) | 형태 |
|---|---|---|
| presenter | 자막·번역 → 녹화 시작/중지 → AI 회의록 켜기/끄기 → 효과 | 녹화·AI 회의록 = `menuitemcheckbox`(`aria-checked`). 자막·번역·효과 = `menuitem` + `aria-haspopup="dialog"`(시트를 연다) |

### 15.3 사이드 패널 탭

- **탭 4개, 순서 고정 : 채팅 · Q&A · 설문 · 참가자**(A-7). 마크업은 `role="tablist"`/`tab`(`aria-selected`·`aria-controls`)/`tabpanel`, 키는 ←→·Home·End.

- Q&A : 추천은 `aria-pressed` 토글이다. presenter 가 [답변함]을 누르면 그 질문은 아래 '답변함 N개'로 접힌다. 목록은 20개 단위 페이지(데이터 패칭 표준 ①, 기존 `pagination.tsx` 를 축약해서 씀).
- 설문 : **1인 1표**(계획서 SA4)라 선택지는 라디오다. Jitsi 의 복수 선택은 채택하지 않았다 [R9]. 검증은 질문 500자·선택지 200자(sql/008 칼럼 길이 = 화면·서버 `POLL` 상수), 선택지 2~10개, 중복 금지. 결과 막대는 막대와 함께 숫자('45% (9표)')를 글자로 보인다.

### 15.4 자막 오버레이 · 자막 시트

| 항목 | 값 | 근거 |
|---|---|---|
| 위치 | 무대 하단 가운데. 바가 보이면 바 위 12px, 바가 숨으면 무대 하단 16px(+`safe-area-inset-bottom`). 위치 이동은 200ms. 가로 회전(`landscape-short`)에서는 바가 오른쪽이라 하단 16px | Jitsi 는 툴바가 보이면 자막을 위로 올린다 [R3] |
| 폭 | `max-width: min(92%, 720px)` | Jitsi 의 50vw 는 모바일 세로에서 한 줄에 6~7자밖에 안 들어가 폭을 넓혔다 [R3] |
| 글자 | `calc(var(--cap-scale) * clamp(16px, min(4vh, 4.5vw), 32px))`. 크기 작게 0.85 · 보통 1 · 크게 1.25. CSS 만 쓰고 JS 계산은 하지 않는다 | Jitsi 공식 = `max(floor(0.04 × 화면 높이), 16)`px [R3]. 여기에 폭 기준과 상한을 더했다 |
| 모양 | `bg-black/75`, 글자는 `--foreground`, 줄 높이 1.4, 안쪽 여백 4px 10px, 모서리 8px | Jitsi 는 줄 높이 1.2. 한글 받침이 겹치지 않게 1.4로 했다 |
| 내용 | **최신 자막 1개**(5초 조각 1개) = 화자 이름(`--muted-foreground`) + 문장. 최대 3줄(`line-clamp-3`). 누적하지 않는다 | A-7 의 '1줄'은 **자막 1개**로 해석했다. 모바일 폭에서 글자 그대로 한 줄이면 읽을 수 없다 [확인중 : Agent10] |
| 수명 | 새 조각이 오면 바꾼다. 8초 동안 새 조각이 없으면 사라진다 | 조각 5초 + 여유 |
| 상호작용 | `pointer-events: none` — 무대를 탭하면 그대로 바가 보이거나 숨는다 | Jitsi 와 같다 [R3] |
| 번역 | 언어가 '원문'이 아니면 번역문을 보인다. 번역이 오기 전에는 원문을 먼저 보이고, 도착하면 바꾼다 | SA8 |

```
자막 시트(⋯ → 자막·번역)
┌ 자막·번역 ─────────────────── ✕ ┐
│ 실시간 자막(방 전체)      [ ● ] │ ← presenter 만. 켜면 state 방송
│ 남은 처리 시간 98분             │ ← presenter 만(SPEECH_MAX_MIN)
│ 자막 보기                 [ ● ] │ ← 개인 설정, 기본 켬
│ 언어   [ 원문            ▾ ]    │ ← 네이티브 <select>: 원문 + 설정된 locale
│ 글자 크기  (작게│●보통│크게)     │ ← radiogroup
│ 음성 번역 듣기            [ ○ ] │ ← 언어가 원문이면 숨김. 켜면 원음 20%
└─────────────────────────────────┘
```

- 방 자막이 꺼져 있을 때(청중) 시트 맨 위에 "발표자가 자막을 켜면 표시됩니다" 한 줄을 보인다. 나머지 설정은 그대로 바꿀 수 있다.
- 기본 언어는 '원문'이다. 번역은 과금이라(A-3) 고른 사람만 쓴다. 언어 이름은 `Intl.DisplayNames` 로 그 언어 자체 표기로 보인다.
- 설정(보기·언어·크기·더빙)은 localStorage 에 저장해 다음 입장에도 유지한다.
- 음성 처리 한도에 닿으면 전원에게 토스트를 띄운다 : "음성 처리 한도에 도달해 자막·AI 회의록을 멈췄습니다".
- 더빙 스위치를 켜는 탭이 곧 사용자 제스처다. 이 안에서 `AudioContext.resume()` 을 부른다(Pi Browser 자동재생, 11절 P3). 원음을 낮추는 방식(덕킹)은 Jitsi 도 같다(0.15) [R4].

### 15.5 효과 시트(배경 · 조명 · 소음)

```
┌ 효과 ──────────────────────── ✕ ┐
│ ┌─────────────────────────────┐ │
│ │   내 미리보기(처리 후 송출본)  │ │ ← 16:9, 모바일에서 시트가 무대를 가리므로 둔다
│ └─────────────────────────────┘ │
│ 배경                             │
│ [없음✓][흐리게][▒][▒][▒]         │ ← 썸네일 16:9·최소 높이 48px, 격자(모바일 3열·데스크톱 4열)
│ [▒][▒][▒][＋ 내 이미지]           │ ← 기본 6종 + 내 이미지(✕ 로 삭제)
│ 내 이미지는 이 기기에만 저장됩니다  │
│ 조명 보정                  [ ○ ] │
│ 소음 줄이기                [ ● ] │ ← 기본 켬
└─────────────────────────────────┘
```

- 배경과 조명 줄은 카메라가 있을 때만, 소음 줄은 마이크가 있을 때만 보인다. WebGL 이 없으면 배경 줄 대신 "이 기기에서는 배경 효과를 쓸 수 없습니다"를 보인다. CPU 경로도 WebGL 이 있어야 돌아간다 [R7].
- 선택 표시는 `aria-pressed` + `--accent` 2px 테두리 + 체크 아이콘이다. LiveKit 도 `aria-pressed` 와 2px 테두리를 쓴다 [R6].
- **고르면 바로 적용**한다. 미리보기가 곧 실제 송출이라 [적용] 버튼은 두지 않는다.
- 배경을 처음 고를 때 모델을 내려받는다(약 2.8MB [R7]). 그동안 해당 썸네일에 스피너와 "준비 중…"을 보인다. 실패하면 "배경 효과를 불러오지 못했습니다"를 띄우고 선택을 '없음'으로 되돌린다.
- 프레임이 떨어져 자동으로 끄면 경고 토스트(`--warning`, `aria-live=polite`)를 띄운다 : "기기가 느려 배경 효과를 껐습니다". 선택은 '없음'이 된다.
- 내 이미지는 네이티브 `<input type="file" accept="image/*">` 로 받는다. IndexedDB 에 최대 6장까지 두고, 넘치면 오래된 것부터 지운다. Jitsi 는 localStorage 에 두어 용량이 차면 지운다(`jitsi-04` ②). 서버에는 올리지 않는다(A-8).
- **소음 줄이기는 토글 1개** = `noiseSuppression` + `autoGainControl` 이다. `echoCancellation` 은 늘 켜 두고(끄면 하울링) 화면에 내놓지 않는다. LiveKit·Jitsi 모두 내장 처리를 기본으로 켜고, LiveKit 화면에는 이 토글 자체가 없다 [R4].
- 대기실에는 효과를 두지 않는다. LiveKit 입장 전 화면에도 없다 [R6]. 수요가 확인되면 추가한다.

### 15.8 상세(S2) 공유 링크 3종

```
│ [   Pi 로 결제하고 입장 (3 Pi)   ] │ ← 기존 주 버튼
│ 일정·공유                          │
│ [캘린더에 추가][일정 파일][메일로 초대] │ ← grid-cols-3, h-10, bg-surface-raised
│ 개최자 : 룸 바로가기 · 출석부        │ ← 기존 개최자 줄에 '출석부' 추가
│ [회의록 보기]                       │ ← 종료 후 회의록이 있을 때만(권한 = SA7)
```

- 버튼은 3개를 넘기지 않는다. 링크 대상은 계획서 SA1 그대로다(캘린더 = TEMPLATE 링크, 메일 = 웹 메일 작성 링크와 mailto 중 SA1 이 결정). 상표 없는 이름을 쓴다.
- 외부 링크는 `target="_blank" rel="noopener"` 로 연다. Pi Browser 에서 외부 링크·mailto 가 어떻게 동작하는지는 [확인중 : 실기기].

- 상태 3가지 : **만드는 중**("회의록을 만드는 중입니다…", 5초 간격 조회·최대 2분, 넘으면 '새로 고침' 안내) / **실패**("요약을 만들지 못했습니다 — 전체 기록은 아래에 있습니다", 개최자에게만 [다시 만들기]) / **완료**.
- 세션이 없으면 클라이언트 게이트를 보인다(redirect 금지). 내려받기는 `piFetch` → Blob → 객체 URL 로 한다(15.8 과 같은 이유).
- 데이터 패칭 표준을 따른다 : 캡처·전체 기록은 화면에 들어오기 직전에 불러오고(③), 전체 기록은 페이지로 나눈다(①).
- **[회의록 삭제]**(소유자 = 기록 시작자·ADMIN, 머리 응답 `del`) : 본문 맨 아래, 인라인 2단계 확인(`window.confirm` 은 WebView 가 막을 수 있어 쓰지 않음) → `DELETE /api/notes/[id]`(smn_nt·smn_nt_seg 논리삭제, 이미 지운 회의록을 다시 지우면 조각만 다시 정리 = 멱등) → 내 회의록 목록. 실패는 삭제 영역 안 `role="alert"` 한 줄(본문 유지, 다시 누를 수 있음).
  근거 : 팀장 판정 REJECTED 사유 '회의록 삭제 경로 없음 — 처리방침(삭제 요청 처리)과 불일치' 해소. 버튼 추가 금지 규칙(15.2)은 회의 화면 하단 바 대상이고, 이 화면은 회의 밖 문서 화면이라 예외로 둔다.

- 체크박스를 켜기 전에는 [기록 시작]이 비활성이다. 이유는 바로 아래에 글로 적는다. 버튼 탭이 곧 마이크 권한 제스처다.
- 마이크가 1개라 화자를 구분하지 않는다. 기록에는 '참석자'로 적는다.
- `navigator.wakeLock` 이 있으면 기록 중 화면 꺼짐을 막는다. 없으면 안내 문구를 보인다. 기록 중 페이지를 떠나려 하면 `beforeunload` 로 경고한다.
- 종료하면 `/notes/[id]`(만드는 중 상태)로 이동한다. ADMIN 이 아니면 클라이언트 게이트 "관리자만 쓸 수 있습니다"를 보인다(redirect 금지).
- '최근 노트'가 있는 이유 : 대면 노트는 세미나(S2)가 없어서 이 목록 말고는 다시 찾을 길이 없다.

### 15.12 접근성

- 토글 : 바·시트 밖 버튼은 `aria-pressed`(배경 썸네일·Q&A 추천), 메뉴 안은 `menuitemcheckbox`·`aria-checked`(기존 control-bar 규칙), 시트 안 켜기/끄기는 네이티브 체크박스 + `role="switch"`.
- `aria-live="polite"` : 녹화·AI 기록 시작·종료, 새 설문, 내 질문 답변됨, 효과 자동 끔, 한도 도달. `assertive` 는 오류에만 쓴다(14.5).
- **자막 오버레이는 aria-live 를 쓰지 않는다.** 화면 읽기 사용자는 원음·더빙을 듣고 있어, 자막까지 읽으면 이중 낭독이 된다. 대신 `role="region" aria-label="자막"` 을 둔다.
- 대화상자·시트 : 포커스 가둠, Esc 로 닫기, 닫으면 연 버튼으로 포커스를 되돌린다(기존 `useMenu` 와 같은 규칙).
- 색만으로 전하지 않는다 : 배지 = 색 + 글자, 설문 = 막대 + 숫자, 선택 썸네일 = 테두리 + 체크 아이콘 + `aria-pressed`.
- 새 단축키는 추가하지 않는다.

### 15.13 문구 키 이름 규칙

- 룸 안 : `room.<기능>.*` — `room.captions.*` · `room.effects.*` · `room.record.*` · `room.notes.*`(룸 안 AI 회의록 토글·배지) · `room.polls.*` · `room.qna.*` · `room.dub.*` · `room.consent.*`. 탭 이름은 기존 `room.panel.chat`·`people` 옆에 `room.panel.qna`·`room.panel.polls` 로 둔다. `room.panel.title`(지금 값 "채팅·참가자")은 키는 그대로 두고 값만 탭 4개에 맞게 바꾼다.
- 룸 밖 : 회의록·대면 노트 = `notes.*`, 상세 공유 = `seminar.share.*`, 출석 = `host.attendance.*`, 처리방침 = `privacy.*`.
- 예 : `room.record.start`·`room.record.stop`·`room.record.badge`·`room.record.started` / `room.notes.on`·`room.notes.badge` / `room.captions.title`·`room.captions.room`·`room.captions.show`·`room.captions.lang`·`room.captions.size.{sm,md,lg}`·`room.captions.waiting`·`room.captions.limit` / `room.effects.bg.none`·`room.effects.bg.blur`·`room.effects.light`·`room.effects.noise`·`room.effects.autoOff` / `room.consent.notice`·`room.consent.title`·`room.consent.body`·`room.consent.agree` / `seminar.share.calendar`·`seminar.share.ics`·`seminar.share.mail`.
- ko 원본과 en 을 동시에 고친다. 상표는 금지 : 'AI 회의록'·'캘린더에 추가'·'메일로 초대'처럼 쓴다.
