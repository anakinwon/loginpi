# 대면 노트 전사 정확도 PoC (2026-10-29)

> 계기 : 마스터 실기기 — "정확도가 매우 떨어져서 지금 상태로는 절대 사용 불가"(F-15).
> 녹음 원본·전사 전문은 개인정보라 저장소에 두지 않는다(`voice/` gitignore). 이 문서는 수치만 적는다.

## 1. 시험 조건

| 항목 | 값 |
|---|---|
| 녹음 | 휴대폰 기본 녹음 앱, 5분 3초, AAC 스테레오 48kHz 258kbps |
| 상황 | 대면 대화 2인, 구어체·말 겹침 있음, 평균 음량 -30.1dB(작음) |
| 변환 | 운영 녹음기와 같게 webm/opus 모노 — 조각 32kbps, 전체 파일 64kbps |
| 기준(임시 정답) | 고급 모델(`gemini-pro-latest`) 전체 파일 전사. **사람이 고친 정답 원고가 없어 '기준과의 차이'다** — 정답 원고가 생기면 다시 잰다 |
| 지표 | CER(글자 오류율, 공백·문장부호 제외) = 빠뜨림 + 잘못 들음 + 덧붙임 ÷ 기준 글자 수, 회의 주제어 5개 적중 횟수 |

## 2. 결과

| 방식 | 모델 | CER | 빠뜨림 | 주제어 ① 적중 | 지연(조각 중앙/최대) |
|---|---|---|---|---|---|
| 현재 운영(5초 조각, 문맥 없음) | 3.5-flash-lite | 71.3% | 377자 | **0회** | 1.9 / 3.0초 |
| 조각만 9.5초로 | 3.5-flash-lite | 64.2% | 339자 | 0회 | 2.0 / 2.6초 |
| **0단계**(9.5초 + 상황·제목·직전 2문장 문맥) | 3.5-flash-lite | **61.4%** | 241자 | 0회 | 1.9 / 2.5초 |

| 1단계(기준) | pro-latest | — | — | **8회** | 96초(5분 분량 1회) |

탈락 :

- `gemini-3.5-transcribe`(전사 전용) — JSON 출력 미지원(`parts[].audioTranscription.text` 로만 줌), 전체 파일은 빈 응답, 조각은 기준의 절반(737자)만 적음
- `gemini-3.8-flash` — 회의 내용이 안전 필터에 오탐 차단(`blockReason: OTHER`) — 내용에 따라 막히므로 운영 불가

## 3. 결론

- 조각 방식은 문맥을 줘도 **지어낸다** — 주제어 ①을 전체 파일 방식은 6~8회 맞히고 조각 방식은 모두 0회(다른 말로 지어냄).
- 0단계는 실시간 미리보기를 조금 낫게 할 뿐(CER 71→61%, 빠뜨림 36% 감소) — **사용 가능 수준은 1단계(녹음 원본 보관 + 종료 뒤 정밀 전사)가 필요**하다.
- 1단계 두 모델끼리도 CER 50%대로 다르다 = 녹음이 어렵다(작은 음량·말 겹침). 어느 쪽이 맞는지는 마스터가 들어 보고 정답 원고를 고쳐야 판정된다.
- 파일 시험이라 마이크 설정(소음·에코 제거 끄기)의 효과는 재지 못했다 — 실기기로 확인.

## 5. 1단계 설계 — 마스터 결정 반영

| 결정 | 값 |
|---|---|
| 원본 음성 보관 | **1일**(정밀 전사 뒤 1일 지나면 삭제) |
| 화자 구분 | **화자1·화자2 …** 표기 |

흐름 : 기록 중 원본 녹음기 1개를 별도로 돌려 1분 독립 파일(opus 64kbps)을 서명 업로드 URL로 Storage 비공개 버킷에 직접 올림 → 종료 시 5분 창(1분 파일 5개를 한 요청에) 단위로 정밀 전사(화자 구분·시각, 앞 창 마지막 문장 문맥, 동시 4개) → 정밀 문장으로 실시간 초안 대체(초안 논리삭제) → 요약. 정밀 전사가 실패하면 초안으로 요약(기록 유실 0).

정할 것 : 정밀 전사 모델(pro 96초/5분 vs 3.5-flash 40초/5분 — 정답 원고로 판정), 상태값 추가(`nt_sts_cd` CHECK, `sql/008:63`)·초안/정밀 구분 칼럼(DA 검토), 종료 API `maxDuration` 60→300 + 창 단위 이어 처리.

## 6. 1단계 적용(2026-10-29) — 마스터 결정 : 모델 3.5-flash, 화자 남1~n·녀1~n

| 항목 | 내용 | 위치 |
|---|---|---|
| 원본 음성 | 기록 중 같은 마이크로 1분 독립 파일(opus 64kbps ≈ 480KB) → 서버 경유 비공개 버킷 `smn-note/aud/<노트>/<순번>-<시작 뒤 ms>.<확장자>`(DB 칼럼 없음) | `components/notes/use-raw-audio.ts` · `api/notes/[id]/audio` |
| 정밀 전사 | 종료(RECORDING→SUMMARIZING 1회)에 5분 창 단위. 첫 창 먼저 → 화자가 가장 많은 1분 파일 + 라벨 전사를 **기준**으로 나머지 창(동시 6)에 같이 보내 번호 유지. 시간 예산 240초(남은 만큼만 호출, 30초 미만이면 그 창은 초안 유지) | `lib/note-audio.ts` refineNote · `lib/gemini.ts` transcribeMeeting |
| 화자 표기 | 들리는 성별 + 성별 안 번호 = **남1·녀1 …**(모르면 화자N). 겹쳐 말하면 사람마다 따로 줄 | `note-rules.ts` spkName |
| 초안 대체 | 창마다 정밀 문장을 먼저 넣고 성공하면 그 시간대 초안만 논리삭제 — 실패·빈 결과·시간 부족 창은 초안 유지(기록 유실 0) | refineNote |
| 보관 | 노트 종료 1일 뒤 삭제(종료 때마다 정리), 노트 삭제 시 즉시 삭제. 처리방침·고지 문구 갱신(PRIVACY_VER 2026-10-29) | sweepAudio · removeAudio |
| 종료 API | `maxDuration` 60 → 300초 | `api/notes/[id]/end` |

실호출 시험(같은 PoC 녹음, 내용 미기재) : 5분 한 창 39초 · 82줄. 성별 라벨 판 — 창 A(0~2분) 18초 남1·남2, 창 B(2~5분, 기준 포함) 36초 **같은 남1·남2 유지**, 겹친 말 분리 8·4줄.

남은 한계 : 기준 파일에 없던 새 목소리는 창끼리 같은 번호를 서로 다른 사람에게 줄 수 있다(ponytail — 창을 순서대로 기준 넓히기로 개선 가능). 보관 정리는 노트 종료 때만 돌아, 새 종료가 없으면 1일을 넘겨 남을 수 있다(cron 으로 개선).
