## 5. 검증 방식

- 묶음마다 : 구현 에이전트 → **독립 검토 에이전트(판정 시험 직접 재실행)** → 결함이면 수정·재검토 → 메인 실제 `pnpm build`·`tsc`·규칙 시험·Go 15패키지 → 팀장 승인 → push → Vercel 개별 status 확인
- 밤새 검토에서 FAIL 로 잡혀 고친 주요 결함 : 시험 봇 SRTP 창(T6), 실패할 수 없던 의존 관문, 재개 시 전원 "네트워크 불안정" 오판, 결제 완료·등록 분리(이중 결제 경로), 개최자에게 결제 버튼, **운영 목록·상세 500**(실제 브라우저 QA)
- 실제 브라우저 QA(Playwright, 가짜 카메라 3창) : 1차 룸 전 흐름 통과 · **2차 7/7 통과**(목록 페이지·탭, 상세 개최자/무료/유료, LIVE 전환, 402 안내, 종료 → 엔진 재시작 → 409, 사회 음소거·잠금·켜기 요청, 고정 → 자동 배치). QA 데이터(세미나 14·참가 1·사용자 3)는 논리삭제로 정리
- 2차 QA 미확인 : 실제 Pi 결제 후 "내가 참가한 것" 표시, 카메라 음소거·잠금(마이크만 확인), 동시 종료 경합, 화면공유 고정
