## 2. 핵심 가치 (절대 불가침)

1. Pi Browser 에서 Pi 계정으로 로그인할 수 있어야 한다.
2. Pi Browser 에서 Pi 로 결제할 수 있어야 한다.
3. **설계 정본은 schema.pi 하나** — 표준·모델·DBMS 프로파일·DB 접속 정보는 schema.pi 가 단일 출처이고 dbms.pi 는 연결 API 로 읽기만 한다(복제 금지, MASTER_ROADMAP §3-10).

## 4. 로그인 방식

**Pi + Google 연동(예외, 마스터 2026-11-01)** — DBA 작업은 데스크톱 위주라 일반 브라우저 로그인이 필요. schema.pi 와 같은 방식(Pi Browser 에서 발급한 6자리 연동 코드로 Google 계정 결합, Google 단독 계정 생성 없음). PRD_28 §1.1-2·LOGIN_PLAYBOOK 예외 목록에 dbms.pi 등재 필요(schema.pi 등재도 함께 [확인중 : 마스터]).
계정은 사이트별 별도(사이트별 UUID, SSO·사이트 간 사용자 대조 없음 — PRD_28 §1.1-1).

## 5. schema.pi 연결 방식 — 별도 DB + 연결 API (마스터 2026-11-01, 선택지 B)

| 항목 | 결정 |
|---|---|
| DB | dbms.pi 전용(비운영 `dbms_dev`·`dbms_stg`, 운영 dbms.pi 전용 Supabase). schema.pi DB 를 직접 읽지 않는다 |
| 연결 | schema.pi 가 서버 간 연결 API 를 연다 — dbms.pi 서버만 호출(공유 서명 키 [TBD : env 이름], 브라우저 직접 호출 금지) |
| 읽는 것 | 분류체계(작업 단위)·DBMS 프로파일·타입 매핑(`sql/024` 정본)·DB 접속 목록(이름·DBMS·호스트 표시용만) |
| 접속 비밀 | **복호화는 schema.pi 한 곳에서만** — 비밀번호(`mdl_db_conn`, `DB_PROFILE_KEY` 봉인)는 API 로 내보내지 않는다. 대상 DB 에 대한 SQL 실행(실행계획·통계 조회)은 schema.pi 가 대신 실행하고 결과만 돌려준다(권장안, [확인중 : 1차 설계]) |
| 권한 | dbms.pi 사용자는 schema.pi 계정과 대조하지 않는다 → 연결 API 는 "dbms.pi 서버" 단위로 허가, 분류체계 접근 범위는 [확인중 : 마스터 — 분류체계 초대 방식] |

### 11.0 공통 아키텍처 원칙 (5~7단계 전부)

| ID | 원칙 | 이유 |
|---|---|---|
| A1 | **제어 평면 / 데이터 평면 분리** — dbms.pi(Vercel) = 정의 읽기·승인·실행 지시·상태·지표만. 행 데이터 이동은 실행 워커(데이터 평면)가 한다. Vercel 함수로 행 데이터를 옮기지 않는다 | Vercel 함수 기본 실행 300초·요청·응답 본문 4.5MB 한도[확인중 : Vercel 문서 vercel.com/docs/functions/limitations 재확인 — MASTER_ROADMAP §4.5 의 "300초·5GB" 중 5GB 가 무엇의 한도인지도 함께], 대량 이행은 수 시간 |
| A2 | **워커 = 고객망 로컬 에이전트 우선** — schema.pi 로컬 에이전트(`agent/SchemaPiAgent.java` 1.3.0, JDBC·JNDI)를 실행 워커로 확장. 에이전트가 작업을 받아 가고(outbound 폴링, 고객망 inbound 개방 없음) 결과·지표만 올린다. **지시 경로(dbms.pi 직접 vs schema.pi 중계)는 10절 #2·#6 [확인중]**. 현 에이전트는 문장 해시 승인 + DDL 화이트리스트(CREATE·COMMENT·PK·시퀀스)만 실행하고 DML 을 거부한다 — 행 이동은 이 보안 모델 밖이므로 A10 을 새로 세운다. 클라우드 원천(Supabase 등)용 관리형 워커는 #6 | 사내 Oracle·Tibero 는 클라우드에서 닿지 않는다. 접속 비밀이 클라우드로 나오지 않는다(5절 "복호화는 한 곳" 유지) |
| A3 | **행 데이터는 dbms.pi DB 에 저장하지 않는다** — 오류 행 격리·샘플 대조는 대상 쪽 격리 테이블 또는 에이전트 로컬 파일(**원천 DB 쓰기 금지**), dbms.pi 에는 건수·합계·해시·오류 코드만. 키도 개인정보(이메일 등)일 수 있어 **솔트 해시로만** 저장 | PRD_28 §1.1-1, 제안서 §5(구조·통계만) |
| A4 | **설계 스냅샷 고정** — 실행 시작 때 schema.pi 매핑·규칙을 버전과 함께 스냅샷으로 저장하고 그 버전으로만 실행. 실행 중 설계가 바뀌면 다음 실행부터 반영 | 실행 중 규칙 변경으로 일부만 다른 규칙이 적용되는 사고 차단 |
| A5 | **사람이 적용** — 이행 실행·컷오버·롤백·CDC 시작/중단은 MIG·DA 승인 후. 운영 DB DDL 직접 실행 경로 없음 | MASTER_ROADMAP §3-4, 제안서 §5 적용 경로 |

| A7 | **관측 하나로** — 작업 지연·처리 건수·오류는 F-04 모니터링(이전 후 dbms.pi)과 같은 수집 체계·화면 | 감시 화면 중복 방지 |
