## 3. 개선 과제(P3 — 이번 관문 통과에 영향 없음, 물리·다음 단계 인계)

1. **도서산간여부 이중 원천** : 지역코드(법정동 단위 고시)와 우편번호기본(기초구역 단위 배송 할증) 양쪽에 존재. 키가 달라 3NF 위반은 아니나 값이 어긋날 수 있다 — 물리 단계에서 각 칼럼 용도(정책 고시 vs 배송 할증)를 칼럼 설명에 구분해 적을 것. 데이터 생성 시 S10 상관 편향 대상으로 활용 가능.
2. **국가코드·업종코드 기준 엔터티 없음** : 외부 표준(ISO 3166·KSIC) 식별 코드라 FK 없이 둔다. 물리 단계에서 값 검증은 공통코드(codes.json)로 할지 결정 메모 필요.
3. **PRM 논리 모델 미작성** : CUS 의 PRM 참조(파트너번호·조직코드)는 PRM 개념 모델 기준으로 대조했다. PRM 논리 관문에서 두 PK 의 이름·도메인이 바뀌면 CUS 3개 엔터티(실명인증내역·멤버십포인트내역·고객상담내역)를 함께 고친다.
4. **영역 간 fk 표기 불일치(타 영역 소관)** : CUS·INV·COL 은 `fk:{area, ent, attr}`, ORD·PAY 는 `fk:{ent:'CUS.고객기본', attr}`. 의미는 같으나 물리·적재기가 두 형식을 모두 읽어야 한다 — ORD·PAY 관문 또는 물리 단계 착수 전에 한 형식으로 통일 권고(3절 형식 `fk:{ent, attr}` + area 키 허용).
