## 3. 작성중으로 남긴 엔터티 91개(앱 관문 — 우회하지 않음)

| 사유(앱 checkLogical) | 엔터티 수 | 성격 |
|---|---|---|
| 부분 종속 의심(2NF) — 복합 PK 자식에 부모와 같은 용어 | 46 | 대부분 이력(_H)·상세의 **스냅숏 속성**(예 고객이력.고객명, 상품가격이력.월정액금액) — 설계 의도(현재값 + 이력 쌍)지만 앱은 'remove' 로 막음 |
| 이행 종속 의심(3NF) — 비식별 부모의 일반 속성 중복 | 44 | 조회용 중복(예 청구조정내역.조정금액, 카드자동납부승인내역.청구년월) |
| FK 상속 누락(역할명 필요) | 4 | 청구계정기본(고객주소상세.고객번호)·요금계산내역(사용량월집계.서비스관리번호)·청구조정내역(청구상세.청구번호)·환불내역(환불계좌상세.청구계정번호) — 같은 용어가 다른 관계로 이미 상속돼 역할명 속성이 필요 |
| 테이블명 25자 초과 | 3 | `PTL_PAY_USE_QTY_CLCT_FILE_L`(27)·`PTL_INV_CARD_ATMT_PAY_APRV_L`(28)·`PTL_INV_CASH_RCIPT_PBLCN_L`(26) — 04 논리 리뷰 A1 에서 '적재 전 판단'으로 넘긴 건 |

(한 엔터티가 여러 사유에 걸릴 수 있음.) 주제영역별 : PRD 8 · CUS 11 · ORD 15 · PAY 19 · INV 15 · COL 10 · PRM 13.
전체 목록 = 적재기 `--dry-run` 출력의 `✗` 줄(엔터티·테이블명·사유 원문).

권고(모델링 담당) : ① 스냅숏 속성은 이력 엔터티의 '변경 전/후' 용어(예 변경전고객명)로 바꾸거나 물리 반정규화로 내린다, ② 조회용 중복은 물리 단계로 옮긴다, ③ FK 4건은 역할명 용어(예 청구계정고객번호) 추가, ④ 테이블명 3건은 약어 조정. 고친 뒤 `--replace` 로 다시 넣으면 자동으로 완료까지 올라간다.

## 4. 결정 메모(위임 모드 — 근거)

| # | 결정 | 근거 |
|---|---|---|
| L1 | 표준은 승인완료(CNFM)로 직접 등록, 승인 신청 이력은 만들지 않음 | 지시 "승인완료 상태로", 앱 일괄등록 `fn_bulk_ins_std_*` 도 CNFM 직접 등록 |
| L2 | 도메인명을 앱 규칙(대표도메인 + 타입 약어 + 길이, 예 `번호V20` → `번호VC20`·`일시TS` → `일시TMP`)으로 재생성. 용어 끝 단어 ≠ 도메인 대표도메인이면 끝 단어 대표도메인을 같은 타입으로 파생(16개, 예 `개월수NM5`), 그 단어를 대표도메인 지정 | 앱 표준 점검 D01·D02·T05(P2) — 설계대로면 P2 위반 55건. 타입·길이 동일이라 물리 영향 없음. 아무 용어도 안 쓰는 설계 도메인 2개(`일련번호N5`·`수량N18`) 미등록 |
| L3 | 단어 1개 용어 8개(공급가액·세액 등 합성어 단어)는 비표준 수용(nstd) | 앱 T01(단어 2개 이상, P2) 예외 경로 = 비표준 수용 용어(행안부 일괄등록과 같은 처리) |
| L4 | 물리 모델 = 앱 `toPhysical`(논리 변환) 결과. 설계 물리와의 차이(반정규화 칼럼·파티션 키 PK 확장·파티션 정의, 54 테이블)는 테이블 설명에 기록, 물리 전용 칼럼 인덱스 9·FK 4 미등록 | schema.pi 칼럼은 논리 속성 없이 존재 불가(CHECK), 다르면 '논리 변경 미반영'으로 테이블 완료가 막힘. DDL 정본은 `ddl/` |
| L5 | ERD = 주제영역마다 LGCL 1개, 그 주제영역 엔터티 **전부**(작성중 포함) + 관계로 이어진 다른 주제영역 엔터티를 격자 배치(폭 300·간격 60, 참조는 오른쪽 열) | 앱 기본 보기 = LGCL. 작성중 엔터티를 미리 배치해 두면 나중에 테이블을 완료해도 ERD 완료 취소가 필요 없다(앱 `phyDgmWhy` 는 배치된 엔터티 허용) |
| L6 | 상태는 앱 관문 그대로 — 엔터티(scopeWhy 0) → 테이블(엔터티 완료 + planSync 0) → ERD(dgmWhy 0). 관문 실패 91개는 작성중 | 지시 "앱 규칙 위반 0" — 운영 DB 직접 쓰기라 우회가 가능하지만 하지 않음 |
| L7 | 분류체계 생성은 앱과 같게 DA 구성원 + 7일 체험(P4 GRACE) + 도메인그룹 8종, 공통코드 사용여부 Y, 물리 모델 식별자 소문자(LOWER) | `api/areas` POST 절차, D4(PostgreSQL DDL 소문자) |
| L8 | `--replace` = 완료 상태 역순 해제 → `area_id·del_yn·del_dtm·modr_id` 를 가진 모든 테이블 논리 삭제 | 물리 DELETE 금지, 잠금 트리거가 완료 행 수정을 막음 |
| L9 | `mdl_subj.lgc_sts_cd`·`mdl_phy_subj` 는 기본값(앱 코드에서 더는 참조 안 함, 상태 단위 = 엔터티·테이블 sql/032) | 앱 src 검색 결과 참조 없음 |

## 5. 남은 위험

- 운영 적용 전 : 대상 ref 확인·`sys_mgrt_hist` 077 확인은 메인 세션 몫(README 절차).
- 체험 7일 뒤 무료 요금제 → 모델·ERD 메뉴 조회 불가(결제 필요).
- 작성중 91개는 모델 수정 전까지 DDL 대상 밖(앱 DDL = 완료 ERD 엔터티 ∩ 완료 테이블).
- 적재기는 schema.pi `src/lib` 순수 함수에 묶여 있다 — 앱 규칙이 바뀌면 같이 따라가지만(장점), 함수 이름·시그니처가 바뀌면 적재기가 실패한다(복제 DB `--dry-run` 으로 먼저 확인).
- 감사 로그는 분류체계 생성 1건(건수 요약)만 남긴다 — 행별 감사(일괄등록의 행별 INS)는 생략.
