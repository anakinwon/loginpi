## 3. 정리·적용

- `chk_all` 삭제 : `DROP SCHEMA CASCADE` 한 번은 잠금 한도(`max_locks_per_transaction`) 초과로 실패 → 상위 테이블 214개를 하나씩 `DROP TABLE CASCADE` 후 스키마 삭제. 결정 메모 : 잠금 한도를 올리는 설정 변경 대신 테이블별 삭제 절차를 README 에 명문화(설정 무변경이 더 안전).
- `pitel` public 적용 : 기존 `ptl_` 테이블 0개(DROP 불필요) → tables 7개 파일만 실행, 오류 0. 결과 테이블 214 · 파티션 하위 2,306 · 인덱스 0 · PK 0(제약은 적재 뒤 메인이 적용, D14). 데이터 0행.
