### 2.3 같은 개념 중복 엔터티 점검

- 영역이 다른 같은 이름 엔터티 0, 테이블명 중복 0.
- 이름이 비슷한 쌍은 개념이 달라 유지 : 단말할부상세(ORD, 할부 회차 일정) ↔ 단말할부청구상세(PAY, 회차의 청구) / 로밍사용내역(PAY, 고객 과금) ↔ 로밍정산내역(PRM, 사업자 간 TAP 정산) / 회선상태이력(ORD, 회선 상태 전 이력) ↔ 이용정지이력(COL, 정지 건의 처리 이력 — 회선상태이력이 이용정지번호 FK 로 참조) / 청구서발행내역(PAY) ↔ 영수증발행내역(INV).
- **판단 메모** : 코드 엔터티 4종(CUS 동의항목코드·PAY 청구조정사유코드·INV 수납채널코드·COL 연체가산금기준코드)은 키 용어가 공통코드(~유형코드)이기도 하다. 값 목록 = codes.json, 엔터티 = 같은 값의 확장 속성(약관 버전·회계 처리·가산율 등)이라 중복이 아니라 "공통코드 + 확장 기준 테이블" 패턴으로 승인. 물리 단계는 두 값 목록이 어긋나지 않게 codes.json 을 적재 원천으로 쓴다.
