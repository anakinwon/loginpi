# MS-SQL 배율 1 초기 적재 실행 기록 (2026-11-15)

> 결론 : **테스트 불가**. 메모리 이상으로 두 번 중단되어, 끊김 없는 한 번의 데이터 적재 시간을 얻지 못했다. 마스터 지시(2026-11-15 "멈추고, 모두 초기화해줘", "2회의 메모리 이상 문제로 인해서 테스트 불가 기록남겨 줘")로 적재를 멈추고 MS-SQL `pitel` DB 를 삭제했다.
> 비교 방식 정본 : dbms.pi `docs/PRD.md` 11.7. 대상 순서 Oracle(완료) → MS-SQL(이 기록) → MySQL.

| 규모 | 배율 1 : 테이블 214개 · 파티션 2,306개 · 1,101,170,707행 · 작업 단위 2,086개 · 동시 7개 |

## 4. 정리

- 두 실행 모두 데이터 적재 시간을 끝까지 재지 못해 PostgreSQL(8,569초)·Oracle(7,120초)과 비교할 수 없다. 중간 완료율은 참고값이며 비교 결론에 쓰지 않는다
- 정리 상태(2026-11-15) : 남은 적재 문장 종료, `pitel` DB 와 데이터·로그 파일 삭제, datagen 진행 상태 파일 삭제. `sql-server` 컨테이너와 max server memory 4,317 MB 설정은 그대로
- 재시험 전 확인할 것 : 적재 프로세스를 Claude Code 백그라운드 작업 밖에서 실행할지, 호스트 메모리 여유를 어떻게 확보할지
