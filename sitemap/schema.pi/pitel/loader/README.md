# schema.pi 적재기 — Pi통신 과금 데이터 표준화(D12)

`load-schema-pi.mjs` : `sitemap/schema.pi/pitel/model/{std,logical,physical}/*.json`·`areas.json` 을 schema.pi 앱 DB 에 넣는다.
분류체계 **Pi통신 과금 데이터 표준화** → 표준(단어·도메인·용어·공통코드, 승인완료) → 프로젝트 **Pi통신 과금 시스템**(접두 PTL·PostgreSQL 0014·업종 TEL) → 주제영역 7 → 엔터티·속성·관계 → 물리 모델(PostgreSQL)·테이블·칼럼·인덱스·FK → 주제영역별 ERD 배치 → 상태(엔터티 → 테이블 → ERD 작성완료).

## 사용법

```bash
node sitemap/schema.pi/pitel/loader/load-schema-pi.mjs --db-url "$URL" --owner <pi_username> [--dry-run] [--replace]
```

| 인자 | 뜻 |
|---|---|
| `--db-url` | 대상 DB 접속 문자열. 값을 명령줄에 직접 치지 말고 환경변수로 넘긴다(출력·로그에 남기지 않음) |
| `--owner` | 소유자 = `sys_user.pi_usr_nm`(활성). 없으면 중단. 분류체계 DA 구성원·등록자·변경자가 된다 |
| `--dry-run` | 한 트랜잭션으로 **전부 넣은 뒤 롤백** — 제약·트리거·잠금까지 실제로 검증하고 아무것도 남기지 않는다 |
| `--replace` | 같은 이름의 활성 분류체계가 있으면 완료 상태를 역순(ERD → 테이블 → 엔터티)으로 풀고 그 분류체계의 모든 행을 **논리 삭제**한 뒤 새로 넣는다. 없이 실행하면 이미 있을 때 중단(멱등) |

- 실행 환경 : Node 22.18 이상(앱의 `.ts` 순수 함수를 타입 제거로 그대로 불러 씀), `postgres` 패키지는 `sitemap/schema.pi/node_modules` 에서 찾는다.
- 한 트랜잭션 : 실패하면 아무것도 남지 않는다.
- 이름·관문 판정은 schema.pi 앱 함수(`entNames`·`domName`·`termNames`·`checkLogical`·`scopeWhy`·`toPhysical`·`planSync`·`dgmWhy`·`cdKind`·`runCheck`)를 그대로 쓴다 — 앱과 다르게 판정하지 않는다.
- 전제(대상 DB) : `sql/001~077` 적용 + 기준 데이터(`std_lgc_tp`·`std_tp_map` = `scripts/db-seed.mjs`) 적재. 논리 타입은 이름(VARCHAR·CHAR·NUMERIC·TIMESTAMP)으로 찾으므로 코드값이 달라도 된다.

## 운영 적용 절차(마스터 직접 실행 — `!` 접두, 메인은 명령·점검표 전달과 dry-run 출력 대조만)

> ⛔ 서브 에이전트는 운영 DB 에 접속하지 않는다(조회 포함). 아래는 **마스터 직접 실행**(`!` 접두, 메인은 명령·점검표 전달과 dry-run 출력 대조만)으로 한다.

1. **대상 확인(메모리 '운영 DB 대상 확인 필수')** — 접속 문자열의 Supabase ref 가 schema.pi 운영 앱(schem.vercel.app)이 읽는 DB 와 같은지, 비운영 ref 가 아닌지 대조한다. 값은 출력하지 않고 ref 일치 여부만 본다.
2. **마이그레이션 수준 확인** — 운영 `sys_mgrt_hist` 에 `077_sys_lnk_tkn.sql` 까지 있는지(읽기 1회). 모자라면 `pnpm db:migrate` 먼저.
3. **소유자 확인** — 마스터의 `pi_usr_nm` 이 운영 `sys_user` 에 활성으로 있는지(적재기가 확인하고 없으면 중단).
4. `--dry-run` 실행 → 출력의 계획 건수·관문·표준 점검이 아래 '복제 시험 기대값'과 같은지 대조.
5. 같은 명령에서 `--dry-run` 을 빼고 실행 → `✓ 적재 완료` 의 건수 대조.
6. 앱에서 확인 : 분류체계 목록 → 표준 점검(준수율 100%·P3 경고만) → 모델 단계 화면(엔터티 완료 123/214) → 주제영역 ERD 7개.
7. 다시 넣어야 하면 `--replace`(기존 것은 논리 삭제로 남음).

## 적재 뒤 알아둘 점

- **7일 체험** : 앱의 분류체계 생성과 같게 요금제4(DA) 유예 7일을 넣는다. 끝나면 무료(표준사전 조회만) — 모델·ERD 를 계속 쓰려면 앱에서 요금제 결제.
- **작성중 엔터티 91개** : 앱 논리 관문(부분·이행 종속 의심, FK 역할명 상속, 테이블명 25자)에 걸려 작성완료로 올리지 않았다(우회 금지). 목록·사유는 `reviews/07_loader.md`. 고친 뒤 앱 '모델 단계'에서 엔터티 → 테이블 순으로 완료하면 된다(ERD 는 이미 그 엔터티를 배치해 두어 완료 취소 없이 들어감).
- **물리 모델 = 논리 변환 기준** : schema.pi 물리 칼럼은 논리 속성에서만 나온다. 설계 물리(DDL)의 반정규화·파티션 키 PK 확장·파티션 정의는 테이블 설명에 기록했고, 물리 전용 칼럼을 쓰는 인덱스 9개·FK 4개는 모델에 넣지 않았다. DDL 정본은 `sitemap/schema.pi/pitel/ddl/`.
