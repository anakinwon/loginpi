## 1. 범위와 기준

- 대상 = 국내 이동통신(MNO) 후불 과금(BSS) 전 과정. 유선·IPTV 는 결합상품의 구성 상품으로만 등장(별도 회선 모델 없음).
- 주제영역 7개 + 업무 모듈 1개, 약어 고정(D4) : **PRD 상품 · CUS 고객 · ORD 가입 · PAY 청구(사용량·요금계산 포함) · INV 수납 · COL 미납 · PRM 파트너** + 업무 모듈 **STL 정산**(D15, 주제영역 아님).
- 참조 체계 : TM Forum SID(정보 도메인 경계) · eTOM(업무 프로세스 경계) · 3GPP 과금(CDR·Rating·CHF) · 국내 이용약관·전기통신사업법·단말기유통법·부가가치세법 관행.
- 이 단계 산출 = **엔터티 후보 이름**(표준단어 + 엔터티 분류어 조합)·유형·설명. 물리 약어·속성·식별자는 다음 단계(개념·논리)가 표준사전과 함께 확정한다.

## 2. 전체 업무 흐름

```
[PRD 상품 정의] ──────────────────────────────────────────────┐
                                                             ▼
가입신청(ORD) → 실명인증(CUS) → 개통(ORD: 가입계약·회선·서비스번호·가입상품·약정·할부)
   │ 유치 판매점(PRM) ──▶ [STL] 유치·판매 수수료 / 장려금
   ▼
사용량 수집(PAY: 원시사용내역·수집파일) → 요금계산 Rating(PAY: 사용내역·기본제공 차감)
   │ 타사 착발신 ──▶ [STL] 상호접속사용집계(PRM)   로밍 TAP ──▶ [STL] 로밍정산(PRM)
   ▼
월 요금계산(PAY: 월정액·일할·사용료·위약금·할부금) → 할인·결합할인 배분 → 청구조정
   ▼
청구작업 Bill Run·마감 → 청구서(청구계정×청구월)·세금 → 청구서 발행(PAY)
   │ 소액결제·콘텐츠 이용료 ──▶ [STL] 제공사 정산(PRM)
   ▼
수납(INV: 자동이체·카드·지로·가상계좌) → 수납배분 → 과오납·환불·선납   [STL] 수납대행 수수료·대사
   ▼ 납기 경과 미수납
미납 확정(COL) → 연체가산금 → 독촉 → 미납 이용정지(→ ORD 회선상태이력) → 직권해지 예고 → 직권해지(→ ORD 계약 종료)
   ▼
채권이관 → 추심 위임·회수([STL] 추심 수수료) / 분할납부 / 신용정보 등록 → 대손 상각 → 대손 회수·채권 매각
   ▼ 조기 해지 시
[STL] 수수료 환수(PRM) → 정산 확정 → 세금계산서 → 정산 지급(PRM)
```

경계 원칙 : **상태의 결과는 실체가 있는 영역에 남긴다** — 미납 이용정지·직권해지의 처리 행위는 COL, 그 결과 회선 상태 변화는 ORD `회선상태이력` 한 곳에 통합(회선 상태 조회 경로 1개).

## 5. 다음 단계(CDC·레이크·AI) 대비 설계 원칙

1. **변경 추적 가능 구조** — 모든 테이블은 PK 필수(논리 복제·CDC 의 행 식별 근거, `REPLICA IDENTITY DEFAULT` 로 충분하게). 상태가 바뀌는 실체·계약(고객·청구계정·회선·가입상품·약정·미납·정산)은 현재값 `~기본` + 변경 `~이력`(유효시작·종료일시) 쌍으로 두어 레이크에서 SCD2 로 바로 쓸 수 있게 한다. 시스템 칼럼은 D7 대로 DDL 에만(LST_MDDTM 이 증분 추출 워터마크 후보).
2. **삭제 방식** — 업무 데이터는 물리 삭제하지 않는다. 해지·취소·철회는 **상태유형코드 + 종료(해지)일시**로 표현(행위 엔터티는 취소 행을 별도 `~취소내역`/음수 조정으로). 삭제여부·삭제일시가 꼭 필요한 기준(REF) 엔터티만 논리 속성으로 둔다(D7 — 시스템 칼럼 아님). CDC 에서 DELETE 이벤트가 사실상 발생하지 않으므로 레이크 이력이 끊기지 않는다. 예외 = 개인정보 파기 기한 도래 시 파기(가명·마스킹 UPDATE 로 처리, 파기 사실은 이력).
3. **대용량 이력 분리** — T4 행위 테이블(원시사용내역·사용내역·요금계산내역·청구상세·수납기본·수납배분상세)은 **월(사용내역은 일) RANGE 파티션** 후보, 파티션 키 = 발생일시·청구월. 현재 상태 조회용 `~기본`과 누적 `~내역/~이력`을 분리해 OLTP 핫 테이블을 작게 유지. 집계(PROC)는 원천과 별도 테이블로 두어 레이크·AI 피처의 재계산 기준점으로 쓴다.
4. **업무 키 보존** — 서비스번호·청구월·청구계정번호 같은 업무 키를 행위 엔터티에도 속성으로 남긴다(조인 없이 레이크 파티셔닝·피처 생성 가능). 반정규화 결정은 물리 단계에서 사유와 함께.
5. **코드·기준은 이력형** — 요금제·요율·정책·수수료 요율은 적용 기간(시작·종료)을 가진다 → 과거 시점 재계산·AI 학습 시 당시 기준 재현.
6. **개인정보 분리** — 식별·연락·주소는 고객 하위 `~상세`로 분리(D11) → 레이크 적재 시 해당 테이블만 마스킹·토큰화.
