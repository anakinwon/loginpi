**2026-11-11 마스터 결정 — 데이터와 메타의 분리**

## 4. 생성 방식

### 4.1 결정적 키 공식

- 모든 값은 행 키 `k` 와 용도 번호 salt 로 만든 해시 난수 `gen.u(k, salt)` 로 정한다(gen.sql 14~16). `random()` 을 쓰지 않으므로 재실행하면 같은 데이터가 나온다.
- 부모 키는 1..N 조밀 정수를 형식화한 값이다. 자식은 부모 번호를 편향 함수로 골라 조인 없이 만든다(77~157행). 그래서 테이블끼리 병렬로 적재할 수 있다(D14).
- 공용 함수(`gen` 스키마)는 실행할 때마다 먼저 적용한다(295행). `--ddl` 을 주면 대상 스키마에 테이블(PK·인덱스 없음)을 만든다(296~301행).

### 4.2 조각(shard)

| 항목 | 값 |
|---|---|
| 조각 수(배율 1) | **2,086** = 조각 17개 테이블 117개(1,989) + 조각 1개 테이블 97개(97) |
| 분할 규칙 | 목표 행이 1,000,000 미만이면 조각 1개(`<테이블>:all`). 그 이상이면 연도 2010~2026 별로 키 범위를 나눠 17조각(`<테이블>:<연도>`, `gen.dtm_to_k` 로 역산) — 251~260행 |
| 조각 1개 | `INSERT … SELECT … FROM generate_series(from, to)` 1문(원자적) |
| 세션 설정 | `SET search_path = <schema>, gen; SET synchronous_commit = off;`(291행) |
| 병렬 | `--jobs` 개 작업자가 조각 큐를 나눠 처리한다(313~333행). 기본은 6이고, 본 적재 실행기는 7을 쓴다 |

### 4.3 재개 상태 파일

- 끝난 조각 id 를 `datagen/state/<db>_<schema>_<scale>.json` 에 기록한다(303~306행). 같은 명령을 다시 실행하면 기록된 조각을 건너뛴다. 머리 주석(5행)의 `<db>_<schema>.json` 은 옛 표기이고, 실제 파일 이름에는 배율이 붙는다.
- 쓰기는 `.tmp` 에 쓴 뒤 rename 하는 원자적 방식이다(322~323행). 그래서 중간에 멈춰도 반쯤 쓴 상태 파일이 남지 않는다.
- 실패한 조각은 `datagen/state/<db>_<schema>_<scale>_fails.json` 에 남고, 종료 코드는 1이다(334~336행).
- `datagen/state/`·`datagen/out/` 은 gitignore 대상이다(`sitemap/schema.pi/.gitignore` 16~17행). 상태와 계획 산출물은 저장소에 넣지 않는다.

### 4.4 실행 명령(`sitemap/schema.pi/pitel` 에서)

```bash
# 계획(SQL 미리보기·볼륨 표) → datagen/out/plan.json·volume.md
node datagen/datagen.mjs plan --scale 1

# 검증 적재(pitel_dev, 작은 배율, 테이블까지 생성)
node datagen/datagen.mjs run --db dev --schema chk_gen --scale 0.001 --jobs 6 --ddl

# 본 적재(로컬 pitel public, 메인 세션만 — CONTEXT 4절) : 실행기가 생성기를 띄운다
node database/run-init.mjs start
#   └ 내부 호출 : datagen.mjs run --db prod --yes --schema public --scale 1 --jobs 7
```

- `--db prod` 는 schema.pi 운영 DB 가 **아니라** 로컬 `pitel` DB 다(`.env.local` 의 `PITEL_DB_URL` 경로에서 DB 이름만 읽음 — 263~269행). `--yes` 가 없으면 생성기가 실행을 거부한다(285행).
- 본 적재 순서(D14)는 테이블 → 데이터 → `ddl/*_constraints.sql`(PK 214 + 보조 318) → `ANALYZE` 다. 실행기 `database/run-init.mjs` 가 이 순서를 진행하고 생성기 로그의 `시작`·`완료` 줄로 테이블별 시각을 기록한다(317~324행).

### 4.5 loader 와의 관계

| | datagen(이 문서) | loader(`loader/load-schema-pi.mjs`) |
|---|---|---|
| 입력 | `model/physical/*.json` · `model/std/codes.json`(38~47행) | `model/{std,logical,physical}/*.json` · `areas.json` |
| 출력 | 데이터 행 → 로컬 `pitel-pg`(`pitel_dev`·`pitel`) | 메타 → schema.pi 앱 DB(분류체계·표준·엔터티·물리·ERD) |
| 운영 반영 | 하지 않음(2026-11-11 결정) | 메타만 schema.pi 운영 public 에 반영(마스터 승인 후 메인 세션) |

두 도구는 같은 물리 모델 JSON 을 정본으로 공유한다. 서로의 출력을 읽지 않는다.
