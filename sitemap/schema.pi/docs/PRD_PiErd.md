## 1. 목적과 범위

DA# Modeler5(엔코아, 데스크톱 MFC)를 기준 제품으로 분석해, 같은 업무를 **웹에서 표준 강제·반자동으로** 수행하는 데이터 모델러를 만든다.

- **목표 흐름** : 논리 모델 완성 → 논리→물리 변환·DDL 생성 → ERD 자동 생성(배치·표시) → 리버스(기존 DB·DDL → 모델)
- **차별점**
  - 모든 이름은 승인 표준단어·용어에서만 만든다(표준 선행).
  - AI·규칙은 추천만 하고, 사용자가 확인해 저장한다(반자동).
  - 리버스할 때 물리명을 **표준 용어로 역매핑**한다. DA#은 리버스 테이블을 표준 비대상으로 둔다(매뉴얼 p170).
- **DA# 참고 원칙** : 기능 개념만 참고한다. 화면·문구·서식·코드는 복제하지 않는다.

## 3. 제품 원칙

1. **ERD는 모델의 뷰다.** 정본은 `mdl_ent`·`mdl_attr`·`mdl_rel`이고, 다이어그램은 배치(좌표·고정·순서)만 저장한다.
2. **물리 모델은 별도 저장한다.** 원천(엔터티·속성·관계 ID) + 사용자 결정값만 두고, 논리가 바뀌면 차이(diff)를 보여 준다.
3. 캔버스 편집도 기존 API로 저장한다. 서버가 이름 표준·관계 제약을 다시 검증한다.
4. 이름은 물리 전환 전까지 대문자이고, 대소문자는 물리 모델 정의 시점에만 고른다(PRD §2.6).
5. 논리 삭제·감사 이력·낙관적 잠금(`ver_no`)을 유지한다. Pi Browser는 쿠키 OR `X-Pi-Token`로 접근한다.
