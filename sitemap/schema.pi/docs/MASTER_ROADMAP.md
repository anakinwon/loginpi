## 1. 한 줄 비전

**표준이 없으면 이름을 만들 수 없고, 모델이 없으면 테이블을 만들 수 없고, 모델이 있으면 이행·복제·분석까지 자동으로 이어진다.**
표준사전(METAPi) → 모델(ModelPi) → ERD(PiErd) → 물리 DB → 이행(PiMig) → 변경 복제(PiCDC·PipeLine) → 분석·레이크(PiAnal). 앞 단계 산출물이 뒤 단계의 **유일한 입력**이다(손으로 다시 입력하지 않는다).

## 3. 공통 원칙(전 단계)

1. **표준 선행** : 모든 이름(엔터티·속성·테이블·컬럼·파이프라인 필드)은 METAPi 승인완료 표준에서만 나온다. 표준 밖 이름은 어느 단계에서도 생성 불가(신청 → 승인 → 사용).
2. **승인·감사** : 단계마다 PRD §3.2 승인 절차와 `std_audit_log` 감사 이력. 물리 DELETE 금지(`del_yn`), 시스템 컬럼 4개 맨 끝.
3. **역할 R&R 7종**(PRD §3.1) 확장 : 1~2단계 = DA·STD·MDL, 3~4단계 = MDL·DA, 5단계 = MIG, 6~7단계 = MIG·QLT·DA. 신규 역할은 만들지 않고 권한표(`src/lib/roles.ts`)에 권한만 추가.
4. **사람이 적용** : DDL·이행·파이프라인 실행은 시스템이 산출하고 적용·실행 승인은 사람(DA·MIG)이 한다. AI 출력은 항상 초안(ModelPi 정규화 추천·PiAnal 튜닝 권고).
5. **단계별 앱 분리**(2026-10-17 마스터 결정) : 제품마다 독립 Next.js 앱·Vercel 프로젝트(`sitemap/<제품>.pi`, METAPi = 현행 schema.pi). 공용 = 로그인(`@pi/auth`·`@pi/guard`)·전용 Supabase(표준·모델 테이블은 한 DB 공유 — 제품별 DB 분리 여부 [확인중 : 2단계 설계 시])·업무 규칙(`src/lib` 공용분은 `packages/`로 추출). 분리 시점은 제품별 착수 시 결정.
6. **Pi Browser 핵심가치** : 로그인·결제 변경은 실기기 검증 후 완료(루트 CLAUDE.md). 데이터 작업 화면은 데스크톱 우선이되 Pi Browser에서 조회는 깨지지 않아야 한다.
7. **외부 전송** : AI(LLM) 호출·외부 DB 접속·레이크 적재는 마스터 승인 뒤([확인중 : AI 키·외부 전송 승인], PRD §10 #10).
9. **DBMS는 2단계로 결정**(2026-10-17 마스터 지시, PRD §2.6) : 표준·개념·논리는 DBMS 무관(도메인 = 논리 데이터타입) → 프로젝트 생성 시 대상 DBMS(예정) 필수 선언 → 물리 모델링까지 이름은 DBMS 무관 대문자 일관 → 물리 모델 전환 시 프로젝트 × DBMS 확정(1:N)·대·소문자 선택 → DDL은 DBMS 프로파일(타입·PK·시스템 컬럼·트리거·FK·인덱스·파티션·함수)로 생성. DB 적용 뒤 DBMS 전환은 PiMig·PiCDC.
8. **반자동이 핵심 철학**(2026-10-17 마스터 지시) : 전 단계에서 사용자가 만들고 AI는 그 시점에 추천만 한다. 추천은 저장하지 않고, 고른 것만 기존 등록 경로로 저장(규칙·승인·감사 그대로). 추천 엔진은 템플릿·규칙 1차 → LLM 2차(같은 API 뒤).
10. **앱 경계 : schema.pi / dbms.pi**(2026-10-19 마스터 지시 — Database 전문지식 2분할). schema.pi = "무엇을, 어떤 이름·구조로 담을지"(설계 시점, DAP 지식 체계), dbms.pi = "담은 것을 엔진이 어떻게 빠르고 안전하게 돌리는지"(실행 시점, DBA·SQLP 지식 체계).

|---|---|---|
| DBMS를 바꿔도 그대로 남는가 | 남는다(DBMS 독립) | 바뀐다(엔진 종속) |

### 4.2 2단계 ModelPi — 데이터 모델링 (현행 ROADMAP 4단계 MD1~MD5)

목표 : 프로젝트 → 주제영역 → 개념 → 논리 → 물리를 표준만으로 설계하고, AI가 정규화를 추천하며 DA가 결정한다.

| 하위 | 내용 | 상태 |
|---|---|---|
| MD1 개념 | 프로젝트·주제영역(2레벨·약어 3자)·핵심 엔터티(표준단어 조합) | ✅ sql/018·019 |
| MD1 잔여 | 엔터티 간 **관계**(식별·비식별·카디널리티·선택성) → 개념 ERD 입력 | ✅ 2026-10-17(`sql/021`) |
| MD2 논리 엔터티 | 주제영역 소속 필수, 이름 = 표준단어 + 엔터티 분류어 | ✅ 2026-10-17(논리 엔터티 추가·수정 — 표준단어 분해·서버 이름 생성, `sql/026`) |
| MD3 논리 속성 | 속성 = 표준용어만(도메인 → 타입·길이 자동), 식별자·서브타입·이력, 코드형은 P04 | 🔶 1차 ✅ 2026-10-17 : 주식별자·필수 속성 추천·선택 등록(sql/025 mdl_attr), 편집(용어 검색 추가·용어 교체, 논리 엔터티 추가·수정, sql/026) |
| MD4 AI 정규화 | 1NF~4NF 위반 탐지·분해안(초안) → 표준 점검 검증기 → DA 채택·기각·이력 | 🔶 1차 규칙 기반 ✅ 2026-10-17(논리 모델 화면 정규화 점검), LLM 2차 [확인중 : AI 키] |
| MD5 물리 | 물리 모델 = 프로젝트 × DBMS 확정(1:N), 프로젝트 접두사(sql/023)+주제영역 3자+단어 약어+접미어, PK·인덱스·반정규화(근거·동기화)·파티션, DBMS 프로파일(Oracle·Tibero·PostgreSQL), 시스템 컬럼 4개 = DDL 생성 때만(표준용어 LST_*) | 🔶 1차 ✅ 2026-10-17(물리 모델·칼럼 그리드·DDL·동기화·변경분 DDL), 인덱스·반정규화·파티션 남음 |

- 데이터 모델(초안) : `mdl_prj`·`mdl_subj`·`mdl_ent`(있음) + `mdl_rel`(관계)·`mdl_attr`(속성 = 용어 참조)·`mdl_key`(식별자)·`mdl_nrm_rcmd`(정규화 권고)·`mdl_phy_*`(물리 옵션). DDL은 da-ddl-guard·DA 승인 후 `sql/021+`
- 완료 기준 : 샘플 프로젝트 1개를 개념→물리까지 표준 위반 0건으로 통과, 승인 절차 적용 여부 결정 반영

### 4.3 3단계 PiErd — ERD 생성·편집 (2단계 ModelPi 완료 후)

- [x] ERD-1 캔버스(2026-10-17) : 엔터티 박스(이름·속성 목록)·관계선(IE 표기 : 까마귀발·식별/비식별 실선·점선·선택성 ○), 개념/논리/물리 뷰 전환(표시 수준만 다름) — 프로젝트 전체 뷰는 마스터 지시로 제거(주제영역 1개 단위, 다른 주제영역 참조 토글)

### 4.5 5단계 PiMig — 데이터 이행

목표 : 원천(현행 DB)과 대상(4단계 물리 모델)을 컬럼 단위로 매핑하고, 변환·실행·검증·롤백을 기록한다.

- [ ] MIG-1 매핑 정의서 : 원천 카탈로그(PHY-3) ↔ 대상 모델 컬럼, 변환 규칙(코드 변환 P04·형식·분할/결합·기본값), 미매핑 목록, 엑셀 왕복
- [ ] MIG-2 실행 계획 : 테이블 순서(FK 위상 정렬)·묶음 크기·병렬도·컷오버 체크리스트(da-migration 에이전트 산출 형식 승계)
- [ ] MIG-3 실행 : 추출 → 변환 → 적재(초기 전량), 실행 로그·오류 행 격리 테이블·재실행
- [ ] MIG-4 검증 : 건수·합계·키 중복·샘플 대조·표준 점검, 결과 보고서(P18 형식)
- [ ] MIG-5 롤백 : 대상 스냅샷·되돌리기 절차, 리허설 횟수 기록
- 실행 엔진 : Vercel Functions(300초·5GB) 한계를 넘는 대량 이행은 별도 워커 [확인중 : 실행 위치 — Supabase 함수·자체 서버·Vercel Queues]
- 완료 기준 : 샘플 원천 → 대상 이행 1회 검증 통과·롤백 1회 성공, 매핑 정의서 엑셀 왕복 손실 0건
