### 2.2 제외

- DA# A/R 서버(Oracle) 직접 연계
- (범위 변경 2026-10-16) DA Modeler 측 모델링 기능은 제외 해제 : §2.5 모델링(개념·논리·물리)으로 포함. DA# Modeler 파일 직접 연계만 제외
- 표준코드(reqst.md FR-14) : ROADMAP 3단계(제안서 P04와 동일 대상). **공통코드 규칙**(2026-10-20 마스터 지시, 모델링 노트 4장 p141~147) : 이름은 ~구분코드(남/녀처럼 값 2~3개·절대 추가 없음 — 서버가 코드상세 4번째 등록 차단 `CD_DIV_TOO_MANY`)·~종류코드(계속 늘어남, 예 서비스종류코드)·~유형코드(유사한 것끼리 묶음·값 4개 이상이거나 추가 가능, 예 거래유형코드·회원등급유형코드) 3종만, 그 외 코드(상태코드 등)는 공통코드 아님 → 별도 기본테이블(기준 엔터티). 코드기본(`std_cd_bas`, **주식별자 = 분류체계 + 코드ID(코드 영문 표준용어 = 코드명 용어 물리명, 예 SEX_DIV_CD)**, 코드형 도메인 확정 용어 1개) : 코드상세(`std_cd_dtl`, 주식별자 = 코드ID + 코드값) = 1:N, 코드값명 상호 배타, 논리 삭제된 같은 키 재등록 = 되살림(sql/060, 구 std_cd·std_cd_val 사용 중단). 등록 = 마스터코드명 + 구분코드|종류코드|유형코드 콤보 → 같은 이름의 확정 표준용어 연결. 명칭 표준 여부는 서버가 '코드명 = 확정 표준용어(코드형 도메인)'로 강제하고, 마스터코드명 표준단어·표준용어 확인(`/codes/master`)은 화면 안내용. 코드기본이 쓰는 용어는 삭제·도메인 변경 불가(TERM_IN_USE_CD). 코드기본 승인 절차(sql/061, 텍스트 대상 키) : 등록·수정·삭제 = 승인대기 → 승인(SYS·DA), 반려 코드기본은 코드상세 등록 불가(CD_BAS_RJCT). 코드상세(코드 인스턴스) 등록·수정·삭제 화면·엑셀 일괄등록 템플릿 ✅ 2026-10-20
- 자동 갱신 구독(PiRC2 `subscribe()`), 기관 SSO

### 2.6 DBMS 선택 시점 (2026-10-17 마스터 지시)

DBMS에 따라 DDL이 달라진다(Oracle 대문자·PostgreSQL 소문자, 데이터 타입, 오브젝트 생성, 함수). 근거 : 데이터 모델링 가이드(04 문단 28) "논리 모델은 DBMS 독립, 물리 모델은 주 DBMS 기준, 다른 DBMS는 타입 매핑으로 변환" · 정의서(01 문단 176·903) "DBMS별 타입 차이는 도메인이 아니라 물리 변환 규칙으로 관리". schema.pi 는 도메인을 논리 데이터타입(`std_dom.lgc_tp_cd`)으로 관리하고 DBMS 29종·DBMS별 물리 타입 매핑(`std_tp_map`)을 보유하므로 표준·개념·논리는 DBMS와 무관하다.

**결정 = 2단계** : 프로젝트 생성 시 대상 DBMS(예정) **필수 선언** → 물리 모델 생성(MD5) 시 **확정**.

**대·소문자 원칙(마스터 지시 2026-10-17)** : 표준·개념·논리·물리 모델링 단계까지 모든 이름(테이블·컬럼·접두사)은 DBMS와 관계없이 **무조건 대문자로 일관**한다. 실제 물리 모델로 전환(DDL 생성)하는 시점에만 사용자가 대문자/소문자를 선택하며, 기본 제안은 프로파일 값(Oracle·Tibero 대문자, PostgreSQL 소문자)이다. **단 PostgreSQL DDL 은 선택과 무관하게 반드시 소문자**(테이블·칼럼·PK·인덱스, 2026-10-18 마스터 지시 — `dbms.ts ddlCase`).

| 단계 | DBMS 의존 | 처리 |
|---|---|---|
| 표준(METAPi) | 없음 | 도메인 = 논리 데이터타입, DBMS별 타입은 매핑표 |
| 프로젝트 생성 | 예정 선언(필수) | `mdl_prj.trgt_dbms_cd`(sql/024, 기존 프로젝트 = PostgreSQL), 업종 기반 추천 칩(금융·공공 → Oracle 계열, 그 외 → PostgreSQL). 식별자 길이 경고를 이 DBMS 기준으로 표시(이름은 대문자 그대로), 언제든 변경(논리 모델 영향 없음) ✅ |
| 개념·논리·물리 모델링 | 없음 | 엔터티·속성·관계·정규화·물리 설계는 DBMS 무관, 이름은 항상 대문자 |
| 물리 모델 전환(MD5) | 확정 + 대·소문자 선택 | 물리 모델 = 프로젝트 × DBMS, 대·소문자 선택(기본 제안 = 프로파일)(1:N — 같은 논리 모델로 Oracle 운영·PostgreSQL 분석/이행 물리 모델 동시 가능), 확정 뒤 DBMS 변경 = 그 DBMS 물리 모델 새로 생성 |
| DDL 생성 | 프로파일 적용 | 선택한 대·소문자 + 아래 DBMS 프로파일로 타입·PK·시스템 컬럼·트리거·시퀀스·파티션·인덱스·함수 생성 |
| DB 적용 후 | 변경 = 이행 | DBMS 전환은 PiMig(이행)·PiCDC(변경 복제) 영역 |

변경 비용 : 표준·개념·논리 0 → 물리 확정 전 0(미리보기만) → 물리 확정 후 = DBMS별 물리 결정(인덱스·파티션·반정규화) 재검토 → DDL 적용 후 = 데이터 이행.

### 3.2 승인 절차 (sql/012, 2026-10-15 마스터 결정)
