### 2.5 모델링(개념·논리·물리) 요구 (2026-10-16 마스터 지시)

근거 : 마스터 지시 5개 항목 · 「데이터 모델링 가이드」(loginpi references 04, 문단 3·15~28·240) · 「AI 기반 Database 설계 가이드」(05, 문단 3·30) · 「데이터 표준체계 정의서」(01) §8.4·§8.5 · 메모리 entity-classifier-table-suffix

**전제** : 모델링은 표준(단어·도메인·용어·엔터티 분류어)이 완성된 뒤 진행하며, 엔터티(테이블)명과 속성(컬럼)명은 표준에 근거하지 않으면 생성할 수 없다. 승인완료(CNFM) 표준만 사용한다.

**핵심 철학 = 반자동(2026-10-17 마스터 지시)** : 사용자가 단계마다 직접 만들고, AI는 그 시점에 추천만 한다(완전 자동 생성 아님). 추천 API는 저장하지 않으며 사용자가 고른 것만 기존 등록 API로 저장한다(이름 규칙·감사 이력 그대로). 1차 추천 엔진 = 업종(Industry) 템플릿 + 표준단어 분해 규칙, LLM은 AI 키·외부 전송 승인 뒤 같은 추천 API 뒤에 추가.

| 시점 | 추천 | 구현 |
|---|---|---|
| 프로젝트 생성 | 업종 8종(이커머스·금융·제조·유통물류·공공행정·의료·통신·교육) 중 프로젝트명·설명에 맞는 업종 | ✅ `sql/022`·`/projects/suggest` |
| 주제영역 생성 | 선택 업종의 주제영역(약어 3자)·주제영역별 핵심 엔터티(표준단어 + 엔터티 분류어), 엔터티 간 관계 | ✅ `/subjects/suggest`·`/relations/suggest` |
| 논리모델링 | 속성(표준용어)·식별자·정규화(4NF) | ⬜ MD2~MD4 |

| MD5 물리 | 승인된 논리 모델을 기반으로 PK·인덱스·반정규화·파티션·튜닝 설계 | 테이블명 `TB_` + 주제영역 3자 + 단어 약어 + 엔터티 분류어 테이블 접미어(_H 등), 컬럼명 = 용어 물리명, PK `PK_테이블명`, 인덱스 `X_테이블명_NN`(PK 포함 최대 5), 시스템 컬럼 4개 맨 끝, 반정규화는 근거·동기화 방안 필수(물리에서만) | 지시 5, 가이드 6·24·240, 정의서 §8.5 |

### 2.6 DBMS 선택 시점 (2026-10-17 마스터 지시)

DBMS에 따라 DDL이 달라진다(Oracle 대문자·PostgreSQL 소문자, 데이터 타입, 오브젝트 생성, 함수). 근거 : 데이터 모델링 가이드(04 문단 28) "논리 모델은 DBMS 독립, 물리 모델은 주 DBMS 기준, 다른 DBMS는 타입 매핑으로 변환" · 정의서(01 문단 176·903) "DBMS별 타입 차이는 도메인이 아니라 물리 변환 규칙으로 관리". schema.pi 는 도메인을 논리 데이터타입(`std_dom.lgc_tp_cd`)으로 관리하고 DBMS 29종·DBMS별 물리 타입 매핑(`std_tp_map`)을 보유하므로 표준·개념·논리는 DBMS와 무관하다.

**결정 = 2단계** : 프로젝트 생성 시 대상 DBMS(예정) **필수 선언** → 물리 모델 생성(MD5) 시 **확정**.

**대·소문자 원칙(마스터 지시 2026-10-17)** : 표준·개념·논리·물리 모델링 단계까지 모든 이름(테이블·컬럼·접두사)은 DBMS와 관계없이 **무조건 대문자로 일관**한다. 실제 물리 모델로 전환(DDL 생성)하는 시점에만 사용자가 대문자/소문자를 선택하며, 기본 제안은 프로파일 값(Oracle·Tibero 대문자, PostgreSQL 소문자)이다.

| 단계 | DBMS 의존 | 처리 |
|---|---|---|
| 표준(METAPi) | 없음 | 도메인 = 논리 데이터타입, DBMS별 타입은 매핑표 |
| 프로젝트 생성 | 예정 선언(필수) | `mdl_prj.trgt_dbms_cd`(sql/024, 기존 프로젝트 = PostgreSQL), 업종 기반 추천 칩(금융·공공 → Oracle 계열, 그 외 → PostgreSQL). 식별자 길이 경고를 이 DBMS 기준으로 표시(이름은 대문자 그대로), 언제든 변경(논리 모델 영향 없음) ✅ |
| 개념·논리·물리 모델링 | 없음 | 엔터티·속성·관계·정규화·물리 설계는 DBMS 무관, 이름은 항상 대문자 |
| 물리 모델 전환(MD5) | 확정 + 대·소문자 선택 | 물리 모델 = 프로젝트 × DBMS, 대·소문자 선택(기본 제안 = 프로파일)(1:N — 같은 논리 모델로 Oracle 운영·PostgreSQL 분석/이행 물리 모델 동시 가능), 확정 뒤 DBMS 변경 = 그 DBMS 물리 모델 새로 생성 |
| DDL 생성 | 프로파일 적용 | 선택한 대·소문자 + 아래 DBMS 프로파일로 타입·PK·시스템 컬럼·트리거·시퀀스·파티션·인덱스·함수 생성 |
| DB 적용 후 | 변경 = 이행 | DBMS 전환은 PiMig(이행)·PiCDC(변경 복제) 영역 |

변경 비용 : 표준·개념·논리 0 → 물리 확정 전 0(미리보기만) → 물리 확정 후 = DBMS별 물리 결정(인덱스·파티션·반정규화) 재검토 → DDL 적용 후 = 데이터 이행.

**DBMS 프로파일(1차 3종, `src/lib/modelpi/dbms.ts`)** — ORACLE(0001) · TIBERO(0013, Oracle 호환 [확인중 : 티베로 기술지원]) · PostgreSQL(0014)

| 항목 | Oracle·Tibero | PostgreSQL |
|---|---|---|
| 식별자(전환 시 기본 제안) | 대문자, 최대 30자(정의서 §8.5) | 소문자(따옴표 없이), 최대 63자 |
| 테이블명 예(전환 후) | `ECM_CST_CUST_M` | `ecm_cst_cust_m`(대문자 선택 시 `ECM_CST_CUST_M`) |
| 데이터 타입 | `std_tp_map`(0001·0013) VARCHAR2·NUMBER·DATE·CLOB | `std_tp_map`(0014) varchar·numeric·timestamptz·text |
| PK | 본질 식별자 또는 NUMBER + 시퀀스, `PK_테이블명` | UUID `gen_random_uuid()` 또는 본질 식별자, `<테이블>_pkey` |
| 시스템 컬럼 | REGR_ID·REG_DTM·MODR_ID·MOD_DTM, SYSDATE | regr_id·reg_dtm·modr_id·mod_dtm, CURRENT_TIMESTAMP |
| 변경일시 갱신 | BEFORE UPDATE 트리거(PL/SQL) | 트리거 함수(plpgsql) |
| FK | 생성 안 함(STD-08) | 생성(PostgREST 조인) |
| 인덱스 | `X_테이블_NN`, PK 포함 ≤5 | `idx_테이블_컬럼`, 6개 이상이면 사유 |
| 파티션 | INTERVAL RANGE | 선언적 RANGE(PARTITION OF) |
| 주요 함수 | SYSDATE·NVL·DECODE·ROWNUM | CURRENT_TIMESTAMP·COALESCE·CASE·LIMIT |

1차 프로파일은 코드 상수, 운영 편집 요구가 생기면 DB 테이블화 [확인중]. 29종 타입 매핑 중 나머지 DBMS는 프로파일 추가로 확장.

### 3.2 승인 절차 (sql/012, 2026-10-15 마스터 결정)

- 1단계 승인 : 신청(DA·STD·MDL) → 승인·반려(DA·STD). 승인권자는 승인 화면에서 본인 신청도 승인 가능(처리자 = 신청자로 기록). 등록·수정·삭제 시 즉시 승인(자기 승인) 선택은 **DA만**, 기본 꺼짐(2026-10-16 마스터 지시) : 그 외 역할은 반드시 승인 화면을 거침
- **최초 등록도 승인완료 후 사용** : 단어·도메인·용어 등록 시 표준 행을 승인대기로 만들고 승인 요청을 같은 트랜잭션에 생성. 용어 구성 단어·도메인 선택·대표도메인명은 승인완료만 허용
- 일괄등록 반영 행 = 승인대기(행마다 요청, 신청사유 '일괄등록'), 승인 화면 묶음 승인(최대 1,000건, 건별 재검증)
- 기존 확정 데이터 = 승인완료 간주(분류체계별 이관 기록 1건)

### 4.3 설계 결정

| 번호 | 결정 | 이유 |
|---|---|---|
| M1 | 단어·용어 분리 저장 | 단어(분류어·금칙어)와 용어(도메인 필수)의 속성·규칙 상이 |
| M2 | 현재 값은 본 테이블, 변경 전후 값은 감사 이력 | DA#의 유효기간 PK 행 복제 방식 대비 PK 단순화·조회 조건 제거 |
| M3 | 동시 수정 = 낙관적 잠금(버전 비교, 충돌 시 409) | 팀 공용 덮어쓰기 방지 |
| M4 | 분류체계 내 단어 논리명, 용어 논리명·물리명, 도메인명 유일 제약 | 화면 검사 누락 시에도 DB 보장 |
| M5 | 용어명은 용어 구성 순서대로 단어를 결합해 생성, 직접 편집 불가 | 현행 Wordict 규칙 승계 |
| M6 | 표준 데이터 상태 = 신청중·확정·폐기 | 승인 절차·논리 삭제 공용 |
