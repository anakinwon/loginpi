후보 원인근거들어맞는 정도가능성
① 보안 계층
(타사 백신 실시간 검사 + DRM)		포맷 전 PC 에 랜섬웨어 미끼 폴더를 만드는 타사 백신과 새 파일을 .exs 로 암호화하는 DRM 이 있었다. 둘 다 파일 쓰기마다 끼어드는 필터 드라이버 방식 — Docker 가상 디스크(vhdx) 쓰기 수백 GB 가 전부 통과처음부터 일정한 2배, 표·조각 구분 없이 균일 — 쓰기당 고정 비용 모양과 일치높음
② Docker 디스크 상태시작 때 220GB 가 이미 찬 가상 디스크(다른 데이터·지운 데이터 공간 재사용), 후반엔 디스크 확장(+84GB) 동반후반 2.3배 상승은 설명, 초반 1.6배는 설명 못 함중간
③ Docker·WSL 버전포맷 뒤 최신판(Docker 29.9.3·WSL 3.0.5) 설치. 포맷 전 버전 [확인중]입출력 경로 개선 가능성은 있으나 2배를 혼자 설명하긴 큼낮음~중간
④ 다른 컨테이너 동시 가동Docker 데이터 390GB(백업 제외 항목) — 다른 컨테이너가 있었음. 그날 가동 여부 [확인중]가동 중이었다면 CPU·메모리 경쟁으로 일정 비율 감속 가능낮음~중간
⑤ 코드·설정·하드웨어·절전설정 15개·동시 7·조각 계획 동일, 같은 노트북, 4분 넘는 공백 없음배제없음
판단 — ①이 주원인, ②가 후반 가중. ③·④는 기록이 없어 단정 불가 [확인중 : 아래 재현 시험으로 확정]

結 결론5. 시사점·후속 조치 (1/1)

pitel 재구축
적재 시간 차이 분석
시사점

재구축 기준 시간을 2시간 23분(data)·3시간 37분(전체)으로 바꾸고, 보안 프로그램 재설치 때 Docker 경로 검사 제외를 지킨다

운영 기준

  • REBUILD.md 예상 시간 : data 2시간 23분 · 전체 3시간 37분 (깨끗한 환경 실측)
  • 적재 중에는 다른 컨테이너를 멈춘다 (오늘 조건 = 기준 조건)
  • 백신·DRM 을 다시 설치하면 실시간 검사 제외에 Docker 데이터 폴더(%LOCALAPPDATA%\Docker\wsl)를 등록 — 회사 정책상 불가하면 기준 시간 × 2 로 잡는다
  • 가상 디스크는 데이터를 지워도 줄지 않는다 — 큰 적재 전 디스크 정리(압축) 여부 확인

원인 확정용 재현 시험 (선택)

시험방법보는 것
A. 컨테이너 경쟁배율 0.01 을 샘플 DB 5종 켠 채 / 끈 채 각 1회소요 비
B. 보안 계층보안 프로그램 설치 후 검사 제외 없이 / 있이 배율 0.01소요 비
C. 디스크 확장새 가상 디스크 vs 꽉 찬 디스크에서 배율 0.01후반 감속

배율 0.01 은 약 1,100만 행 · 수십 분이면 끝나, 한 번에 한 조건만 바꿔 비교 가능

결론 — 이번 단축은 생성기 개선이 아니라 포맷으로 사라진 보안 계층·오래된 디스크 비용이다. 같은 성능은 같은 환경 조건이 지켜질 때만 재현된다.
