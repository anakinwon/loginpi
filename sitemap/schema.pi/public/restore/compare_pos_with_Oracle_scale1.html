7. 원인 분석

원인 분석

시간 차이의 주원인은 PostgreSQL 가중 선택 함수의 plpgsql 호출이고, Oracle 의 행당 고정 비용이 그 이득의 일부를 깎았다

#원인 후보근거가능성
1PostgreSQL gen.wpick 이 plpgsql 이라 질의 안에 펼쳐지지 못함호출 1회 14.07 µs(그 밖의 SQL 함수 0.86 µs 의 16배). 가중 선택이 많은 테이블일수록 Oracle 이 빨라짐(0개 2.16배 → 3개 이상 0.57배). 고객 이력 ptl_cus_cust_h 는 0.32배높음
2Oracle 행마다 고정 비용이 PostgreSQL 의 2배고정 비용 13.85 µs · 6.87 µs. 단순 테이블(가중 선택 0개) 5개 모두 Oracle 이 느림(가입 신청 상세 ptl_ord_sbsc_aply_d 3.14배). 후보 : CONNECT BY 행 생성기, 일반 INSERT 의 undo·redo 기록(블록 변경 207,681,616회). 둘의 몫은 나누어 재지 않음높음
3그 밖의 생성 함수 비용Oracle 1.33 µs · PostgreSQL 0.86 µs. 펼친 식에서 같은 해시를 CASE 분기마다 다시 계산(예 가중 선택 한 번에 ORA_HASH 가 선택지 수만큼). 영향은 고정 비용보다 작음중간
4디스크 쓰기 속도Oracle I/O 대기 4.5%, CPU 93.9%. 두 DB 데이터 크기 174.9 · 172.7 GB 로 같음낮음
5메모리 크기(SGA 3GB · shared_buffers 2GB)계산이 묶은 작업이고 읽기 대기가 작음(db file sequential read 40초)낮음
6실행 순서·동시성 차이같은 작업 단위 2,086개·같은 순서·동시 7개, 두 DB 세션 가동률 99.9%배제
판단 : 이번 차이는 엔진 쓰기 성능보다 생성식 계산 방식에서 나왔다. 회귀로 추정하면 gen.wpick 을 SQL 식으로 바꿀 때 PostgreSQL 적재가 약 72분 줄어 Oracle 보다 빨라질 수 있다(추정, 9장 재측정으로 확정).

※ 출처 : 6장 비용 모형, 5장 Oracle 통계, oracle/out/full_analysis.json(테이블별 소요 비교)

시사점과 후속 조치

11억 행 적재는 Oracle 1시간 58분 40초 · PostgreSQL 2시간 22분 49초로 끝났고, 다음 비교는 MS-SQL, 마지막은 MySQL이다

시사점

  • DBMS 비교의 첫째 측정값은 시간 · 작업 건수 · 완료율이다. 10분 단위 표와 주제영역별 표를 같은 도구(bench/progress.mjs · bench/analyze.mjs)로 남긴다
  • 적재 시간은 엔진보다 생성 방식에 크게 흔들린다. 엔진마다 생성식을 바꿀 때는 함수가 질의 안에 펼쳐지는지(인라인)를 먼저 본다
  • Oracle 은 행마다 고정 비용이 크다. 단순 테이블이 많은 업무는 PostgreSQL 이 유리하다
  • 두 DB 의 데이터 크기는 같다(174.9 · 172.7 GB). 저장 공간은 DBMS 선택 기준에서 차이를 만들지 않았다
