감독·검토·승인·테스트 = master-svc-agent-leader(teamanakin-admin 승인 단계). 세 사이트는 **테스트 목적**이라 결제 없이 효과를 바로 붙인다(마스터 지시 2026-10-13) — `EFCT_TRIAL_DOMAINS`(src/lib/site.ts) 예외, 검증이 끝나면 비운다. 세 사이트는 자사(`own_site_yn='Y'`)이기도 해서 예외를 비워도 관리자 선택만으로 계속 노출된다.

## 2. 상품 규칙 (반짝임 §10 과 같은 구조)

- **선택** : 신청·수정 폼(소유자)과 관리자 수정 폼의 콤보 "버블 이펙트"(없음·궤도·펄스·혜성) → `site_mst.efct_cd`. 결제된 이펙트는 소유자가 바꿀 수 없다(서버 강제, `efct_pymnt_id` 있으면 현재값 유지). 관리자는 바꿀 수 있고, 자사는 결제 없이 노출
- **결제** : ① 합산 — 신청(APPLYING, 사용료 미결제)에 이펙트가 있으면 `prepare`(kind=REG) 가 사용료+반짝임+이펙트 단가를 합산하고 `metadata.efct=<코드>`, `fn_cmpl_site_reg_pymnt`(017 재정의) 가 같은 결제ID 로 `efct_pymnt_id·efct_pay_dtm` 기록 ② 단독 — 사용료 결제 뒤(SPK_PAYABLE_STS) `/pay/<id>?kind=efct` → prepare kind=EFCT(type `SITE_EFCT`) → `fn_cmpl_site_efct_pymnt`(상태 불변, 멱등). approve 는 사이트 현재값(`efct_cd`)으로 정가 재계산 + `metadata.efct` 일치 검증
- **노출** : `effectOn` = efct_cd 있음 AND (efct_pay_dtm NOT NULL OR own_site_yn=Y OR 시연 도메인), IN_USE 버블만(/api/bubbles `effect`). 재등록 시 `efct_pymnt_id·efct_pay_dtm` 초기화(새 주기 = 새 결제)
- **단가** : `fee_plan` EFFECT × 요금제 5행(`EFCT_<plan>`, 3종 공통) = 사용료의 15% **[확인중 : 마스터]** — BSC1 1.5 · BSC2 3.75 · PRM1 6.75 · PRM2 12 · VIP 19.5 Pi. UPDATE 로 변경, 판매 중단은 use_yn='N'
- **표시** : 툴팁·aria-label 에 "🪐 궤도 이펙트" 등 번역명(`efct.<코드>`), 내 사이트·관리자 상세에 아이콘+이름+결제 여부, 결제 화면 행 "버블 이펙트"
- **샘플(데모)** : 유료 요금제마다 두 번째 샘플 사이트에 궤도→펄스→혜성 순환(`EFFECT_SAMPLE`, api/bubbles) — 샘플은 DB 미시드·"샘플" 배지 유지

## 3. 렌더 설계 (src/components/effects)

공통 계약 `types.ts` — `EffectProps { r, color, stage 0~3, id }`, 렌더 위치 = 버블 `<g>` 안 요금제 링 다음·로고/글자 앞, 좌표계 버블 중심(0,0), 색 = 요금제 반짝임 팔레트(`PLAN_SPARKLE`), `pointerEvents` none. 등록 `index.tsx` `EFFECTS[efct_cd]`. 스타일(`.efct-*`)은 반짝임처럼 `globals.css` 에 직접 둔다 — dev Turbopack 이 별도 파일 `@import` 를 누락해 애니메이션이 전혀 돌지 않았던 사고(2026-10-13, 빌드 산출물엔 포함돼 로컬에서만 재현).

| 효과 | 기법                                                                                                                                                                                                                                                                                                                                         | 구성(단계·기기 무관 — 모바일 동일, 마스터 2026-10-13) |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 궤도 | 토성형 — 타원 고리(rx r×1.32·ry r×0.42, −20° 정적 transform 속성)를 점선 굵기 4px(1차 2배 → 2차 다시 2배)로 그리고, 같은 타원에 `pathLength=100` + 아주 짧은 대시(둥근 linecap = 점) + `stroke-dashoffset` 회전으로 위성이 40초에 한 바퀴 천천히 돈다. 마스크로 버블 뒤를 지나는 위쪽 반원 구간을 가려 고리·위성이 버블 뒤로 들어갔다 나온다 | 항상 점선 고리 + 위성 2(반대 방향·64초) + 위성 1 glow |

| 혜성 | 같은 원(r×1.08)에 `pathLength=100` 원을 겹쳐 대시 길이·opacity·굵기를 층별로 두고(머리 1.5%·굵기 2배·glow → 꼬리 14·32·60%) 같은 `stroke-dashoffset` 애니메이션(28.8초 반시계) = 긴 그라데이션 꼬리를 끌며 머리가 돈다                                                                                                                       | 항상 4겹                                              |

**모바일 WebView 철칙**(TROUBLESHOOT 2026-10-12 반짝임 사고) : SVG 요소에 CSS `transform` 애니메이션 금지 — `stroke-dashoffset`·`opacity`·SMIL 만 사용. `prefers-reduced-motion` 은 정지 대신 **3배 감속**(SMIL 은 미디어쿼리를 못 읽어 렌더 시 `matchMedia` 로 주기 조정).
