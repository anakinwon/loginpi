# 요청 재수행 (work:resume)

작업 이력 대시보드(`work-statistics/mywork/myClaudeModelChage_4_myWorkStyle.html`)에 있는 요청 1건이 끝났는지 판정하고, 끝나지 않았으면 Claude Code 로 다시 실행하는 명령을 만든다.
CLI `scripts/request-resume.mjs`, 표·CLI·엑셀이 같이 쓰는 판정 함수 `scripts/work-history-rows.mjs`.

## 1. 작업 상태 판정 (레코드 값만 봄)

| 상태 | 기준 | 재수행 |
|---|---|---|
| 완료 | `ts_res`(응답 시각) 있음. mid-turn 에 흡수됐다가 다음 응답 시각으로 보정된 턴(`ts_res_src='mid_turn'`)도 포함 | `--force` 일 때만 |
| 진행 중 | 응답 시각 없음 + 아래 어디에도 해당 없음 = 지금 실행 중인 세션의 마지막 턴 | 대상 |
| 중단 | `interrupted` (사용자가 Esc 로 멈춤) | 대상 |
| 응답 없음 | `absorbed`(보정 안 됨, 응답 문장 없이 끝남) 또는 `incomplete`(세션이 턴 도중 끝남) | 대상 |
| 대체됨 | `superseded` (응답 전에 다음 요청이 들어옴) | 대상 |

**후속 처리됨 [확인중]** (보조 표시 — 상태는 그대로) : 미완료 요청 중, 같은 세션의 바로 다음 1~3턴이 그 요청을 이어간 신호가 있는 것. 신호는 레코드 값만 본다 — 다음 요청이 '이어서·계속·다시'로 시작 / 15자 이하 짧은 재지시 / 원 요청 앞 20자로 시작(같은 요청 다시 입력) / 커밋·배포 유형 턴이 원 요청과 핵심어가 겹침. 대시보드 상태 필터 `미완료 — 후속 없음` 은 이 행을 뺀다. CLI 는 이 턴~뒤 3턴 사이 세션 기록의 `git commit` 메시지도 참고로 보여 준다(판정에는 안 씀).

`[Request interrupted by user …]` 같은 중단 표식은 요청이 아니다 — 표식뿐인 턴은 목록에서 빠지고, 그 id 를 넣으면 `중단 표식 — 실제 요청은 <앞 턴>` 으로 안내한다.

세션이 지금도 살아 있는지는 프로세스를 직접 볼 수 없다. 그래서 세션 기록 파일(`~/.claude/projects/*/<세션>.jsonl`)의 마지막 수정 시각(10분 안이면 살아 있을 수 있음)과, 같은 세션에 뒤 요청이 이어졌는지로 추정한다. 그래서 출력에 `[확인중]` 이 붙는다.

## 2. 번호·ID 찾는 법

- 대시보드 **상태** 필터에서 `미완료 전체(진행 중+중단+응답 없음)` 를 고르면 재수행할 요청만 남는다.
- 행의 **재수행** 버튼을 누르면 `pnpm work:resume <세션8자>:<턴>` 이 클립보드에 복사된다. 터미널에 붙여 넣으면 된다.
- `#` 칸에 마우스를 올리면 레코드 id(`<세션 id>:<턴>`)가 보인다.
- `#` 번호는 연도·월·상태 필터를 모두 `전체` 로 둔 순서(최신순)다. 새 요청이 들어오면 번호가 밀리므로 id 를 쓰는 편이 안전하다.

입력은 셋 중 하나를 쓴다 : `# 번호`(예 `12`), 레코드 id(예 `8906cfd4-…:14` 또는 `.1` 포함), 세션 앞부분[:턴](예 `8906cfd4:14`, 턴을 빼면 그 세션의 최신 턴).

## 3. 실행 예

```bash
pnpm work:resume 8906cfd4:14                # 판정 + 재수행 명령만 출력 (dry-run, 기본)
pnpm work:resume 12 --mode new              # 새 세션에 원 요청문 + "이전 결과 확인 후 이어서" 지시
pnpm work:resume 8906cfd4:14 --run          # 요청문을 보여 주고 y 확인 뒤 실행
pnpm work:resume 8906cfd4:14 --run --print  # 비대화형(claude -p)으로 실행
pnpm work:resume 3 --force                  # 완료된 요청도 다시 실행 명령 만들기
```

- `--mode resume`(세션 기록·작업 폴더가 있으면 기본) : `claude --resume <세션 id> "<이어서 지시>"`. 세션이 살아 있을 수 있으면 `--fork-session` 을 붙여 새 id 로 갈라서 실행한다(원 세션과 충돌 방지). 명령은 세션이 기록한 작업 폴더에서 실행한다.
- `--mode new` : 저장소 루트에서 새 세션 `claude "<원 요청문 + 이어서 지시>"` 를 실행한다. 작업 폴더(삭제된 워크트리 등)가 없으면 이 모드가 기본이다.
- `--yes` : 실행 전 확인을 건너뛴다. `--from <ISO시각>` : 대시보드의 `--from` 과 같은 기준 시각을 쓴다.
- 화면에 나오는 요청문은 마스킹된 값이다(경로·비밀값·UUID). 실제로 실행할 때는 원문을 쓴다.

데이터 위치 : `$WORKSPACE_ROOT/loginpi/work-history`(바꾸려면 `WORK_HISTORY_DIR` 지정). 워크트리에서 실행해도 원래 체크아웃의 기록을 읽는다.
