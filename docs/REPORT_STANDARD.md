# 보고서 작성 표준

> 분석·비교·원인·현황 보고서와 장표("장표로 만들어 줘"), 문서를 만들 때의 기준. 모든 시스템(cafe.pi·sitemap.pi·schema.pi·dbms.pi 등)에 같이 적용한다.
> 견본 : `sitemap/schema.pi/public/restore/differ.html` (pitel 적재 시간 차이 분석, 2026-11-14)
> 제정 : 2026-11-14 마스터 지시
> 개정 : 2026-11-14 문체 규칙(3절) 추가

## 1. 구성 : 기승전결

보고서는 **기 → 승 → 전 → 결** 순서로 장을 놓는다. 단계는 흐름으로 지키고 화면에 적지 않는다. '起 질문'·'承 사실' 같은 단계 이름, 칩, 구성 안내 줄을 장표에 쓰지 않는다. 읽는 사람이 단계 이름 없이도 흐름을 따라가게 쓴다.

| 단계 | 담는 것 | 장 예시 |
|---|---|---|
| 기 | 보는 대상과 이유 : 답할 물음 한 줄(짧은 말로), 핵심 숫자, 비교 대상, 근거 자료. 결론 한 줄 미리보기 허용 | 표지, 요약 |
| 승 | 측정·조회한 사실 : 조건 비교표(같음·다름 판정), 수치표, 차트. 해석은 넣지 않는다 | 조건 비교, 데이터 분석 |
| 전 | 사실에서 드러난 핵심과 반전 : 원인 후보(근거·들어맞는 정도·가능성). 배제한 후보도 넣는다 | 원인 분석 |
| 결 | 판단 한 문장, 시사점, 후속 조치(확정 시험·담당·상태) | 시사점·후속 조치 |

- 승(사실)과 전(해석)은 다른 장에 둔다. 한 장에 섞으면 데이터와 해석의 경계가 흐려진다
- 장 수는 내용에 맞춘다(견본 7장). 단계마다 1장 이상

## 2. 쉽고 명료하게

- 한 장에 메시지 하나. 제목 아래 **거버닝 한 문장**으로 그 장의 결론을 먼저 말하고, 핵심 낱말은 색으로 강조한다
- 짧은 문장을 쓴다. 전문용어는 괄호로 풀이한다. 숫자에는 단위를 붙이고, 변화는 `이전 → 이후`와 배수로 보인다(예 `4시간 43분 → 2시간 23분 · 1.99배`)
- 장 끝은 한 줄 띠(Key Finding / 시사점 / 판단 / 결론)로 닫는다
- 가능성·판정은 칩(높음·중간·낮음, 동일·다름)으로 보인다

## 3. 문체 (반드시 지킬 것)

보고서와 문서의 모든 글(제목·거버닝·본문·표·띠·출처)에 적용한다.

| # | 쓰지 않는 표현 | 대신 쓰는 표현 | 예 |
|---|---|---|---|
| 1 | 길고 꾸민 제목·질문형 문장 | 짧고 평이한 말 | `같은 코드·같은 노트북인데 왜 적재 시간이 절반이 되었나` → `같은 환경, 결과가 다른 이유` |
| 2 | `~이 아닌(아니라) ~이다` 대조 구문 | 말하려는 내용만 바로 쓴다 | `코드가 아니라 환경이 원인` → `원인은 실행 환경` |
| 3 | `~은 ~뿐` 한정 구문 | 사실을 그대로 쓴다 | `바뀐 것은 Windows 환경뿐` → `Windows 환경이 바뀌었다` |
| 4 | 줄표 `—`(긴 줄표)·`–`(짧은 줄표) | 쌍점 `:`. 범위는 `~` | `요약 — 2배 느림` → `요약 : 2배 느림` |
| 5 | 연속 정의 `A = B = C`, `A = B : C` | 한 문장에 정의 하나 | `원인 = 보안 = 백신` → `원인은 보안 계층이다. 백신이 그 예다` |
| 6 | `[확인중]`·`[TBD]` 남발 | 결론에 영향을 주는 미확인 값만, 보고서 전체에서 한 곳에 모아 한 번 | 같은 미확인 값을 여러 장에 반복 표기하지 않는다. 결론에 영향 없는 값은 표기 없이 뺀다 |

- 완성 뒤 글자 검사로 `—`, `–`, `아니라`, `아닌`, `뿐`, 한 줄에 `=` 두 번 이상, `확인중`·`TBD` 개수를 확인한다

## 4. 장 형식

- 한 파일 HTML. 외부 리소스(폰트·스크립트·이미지 CDN)를 쓰지 않는다. 16:9 장이고, 좁은 화면에서는 세로로 풀린다
- 표지 : 남색 그라데이션, 큰 핵심 숫자, 비교 대상, 근거 목록
- 본문 장 : 제목 `N. 제목`, 남색 밑줄과 주황 강조선, 우상단 브레드크럼 3줄
- 장 번호 `(i/n)`은 같은 제목이 2장 이상일 때 붙인다(예 `3. 조각별 소요 비교 (1/2)`). 1장이면 `(1/1)`을 쓰지 않는다
- 쪽 번호는 바닥글 가운데에 둔다. 바닥글과 본문 사이에 구분선 한 줄을 긋는다
- 박스 : 진회색 띠 제목과 흰 본문. 출처는 좌하단 `※ 출처 :` 한 줄
- 새 보고서는 견본 파일의 CSS를 그대로 가져다 쓴다(디자인 일관성)

## 5. 정확성

- 수치는 이번에 직접 확인한 근거(로그·쿼리·파일)에서만 가져온다. 이전 결과를 쓰면 그 사실을 밝힌다
- 기록이 없는 값 가운데 결론에 영향을 주는 값만 빨강 `[확인중 : 사유]`로 적는다. 어디에 몇 번 적는지는 3절 6번을 따른다. 추론은 추론이라고 쓰고, 확정 방법(재현 시험 등)을 결 단계에 둔다
- 완성 뒤 헤드리스 브라우저로 장마다 캡처해 잘림·넘침을 확인하고, 본문 숫자 문구를 표·차트 값과 대조한다

## 6. 공개 주의

- `public/` 아래 보고서는 배포되면 누구나 본다. 비밀번호·키·토큰·개인 경로·이메일을 넣지 않고, 환경변수는 이름만 쓴다
- 정적 파일 주소는 확장자까지 쓴다(`/restore/differ.html`). 앱 proxy matcher가 점 없는 경로를 다국어 라우팅으로 넘기기 때문이다
- 배포 뒤 운영 주소에서 200 응답과 본문 문구를 확인한다. 빌드가 실패하면 이전 배포가 계속 서빙될 수 있다
