# 보고서 작성 표준

> 분석·비교·원인·현황 보고서와 장표("장표로 만들어 줘")를 만들 때의 기준. 모든 시스템(cafe.pi·sitemap.pi·schema.pi·dbms.pi 등) 공통.
> 견본 : `sitemap/schema.pi/public/restore/differ.html` (pitel 적재 시간 차이 분석, 2026-11-14) · 제정 : 2026-11-14 마스터 지시

## 1. 구성 — 기승전결

보고서는 **기 → 승 → 전 → 결** 순서로 장을 배치한다. 단계는 **흐름으로만 지키고 화면에 적지 않는다** — '起 질문'·'承 사실' 같은 단계 이름·칩·구성 안내 줄을 장표에 쓰지 않는다. 읽는 사람이 단계 이름 없이도 흐름을 따라가게 만드는 것이 목표다.

| 단계 | 담는 것 | 장 예시 |
|---|---|---|
| 기 | 무엇을 왜 보는가 — 질문 한 줄, 핵심 숫자, 비교 대상, 근거 자료. 결론 한 줄 미리보기 허용 | 표지, 요약 |
| 승 | 측정·조회한 **사실만** — 조건 비교표(같음·다름 판정), 수치표, 차트. 해석 섞지 않음 | 조건 비교, 데이터 분석 |
| 전 | 사실에서 드러난 **핵심·반전** — 원인 후보(근거·들어맞는 정도·가능성), 배제한 후보까지 | 원인 분석 |
| 결 | **판단 한 문장 + 시사점 + 후속 조치**(확정 시험·담당·상태) | 시사점·후속 조치 |

- 승(사실)과 전(해석)은 **다른 장**에 둔다 — 한 장에 섞으면 어디까지가 데이터인지 흐려진다
- 장 수는 내용만큼(견본 7장). 단계마다 1장 이상

## 2. 쉽고 명료하게

- **한 장 = 메시지 하나.** 제목 아래 **거버닝 한 문장**으로 그 장의 결론을 먼저 말하고, 핵심 낱말은 색으로 강조
- 짧은 문장. 전문용어는 괄호로 풀이. 숫자엔 단위, 변화는 `이전 → 이후`와 배수(예 `4시간 43분 → 2시간 23분 · 1.99배`)
- 장 끝은 **한 줄 띠**(Key Finding / 시사점 / 판단 / 결론)로 닫는다
- 가능성·판정은 글보다 칩(높음·중간·낮음, 동일·다름)으로

## 3. 장 형식

- **한 파일 HTML**, 외부 리소스(폰트·스크립트·이미지 CDN) 없음. 16:9 장, 좁은 화면에선 세로로 풀림
- 표지 : 남색 그라데이션 + 큰 핵심 숫자 + 비교 대상 + 근거 목록
- 본문 장 : 제목 `N. 제목 (i/n)` + 남색 밑줄·주황 강조선 + 우상단 브레드크럼 3줄 + 오른쪽 아래 쪽 번호
- 박스 = 진회색 띠 제목 + 흰 본문. 출처는 좌하단 `※ 출처 :` 한 줄
- 새 보고서는 견본 파일의 CSS 를 그대로 가져다 쓴다(디자인 일관성)

## 4. 정확성

- 수치는 **이번에 직접 확인한 근거**(로그·쿼리·파일)에서만. 이전 결과를 쓰면 그 사실을 밝힌다
- 기록이 없는 값은 빨강 `[확인중 : 사유]`. 추론은 추론이라고 쓰고, 확정 방법(재현 시험 등)을 결 단계에 둔다
- 완성 뒤 헤드리스 브라우저로 **장마다 캡처**해 잘림·넘침을 확인하고, 본문 숫자 문구를 표·차트 값과 대조

## 5. 공개 주의

- `public/` 아래 보고서는 배포되면 **누구나 본다** — 비밀번호·키·토큰·개인 경로·이메일 금지, 환경변수는 이름만
- 정적 파일 주소는 확장자까지(`/restore/differ.html`) — 앱 proxy matcher 가 점 없는 경로를 다국어 라우팅으로 넘긴다
- 배포 뒤 운영 주소에서 200 + 본문 문구 확인(빌드 실패 시 이전 배포가 계속 서빙될 수 있음)
