### 4-3. 3단계

`std_syn`·`std_ban`·`biz_glos`·`biz_subj`·`biz_tag`(접두사 `biz_` 신규)·`mdl_tbl_ver`·`mdl_prg`·`mdl_prg_ref`·`sys_cfg` — 수요 발생 시 설계.

**신규 표준단어·도메인 등재 선행** : §4 전 컬럼명을 `_` 토큰으로 나눠 `데이터표준규칙.md` §9 약어 목록 + §1-2 도메인 + v2.2 등재분(sql/176, `chg`·`tbl`·`rsn` 등 10종)과 대조한 미등재 후보 — `mdl`·`prf`·`biz`·`clct`·`chk`·`rslt`·`sevr`·`rule`·`obj`·`qry`·`exec`·`tup`·`blk`·`rcmd`·`expct`·`efct`·`msr`·`bef`·`aft`·`syn`·`ban`·`glos`·`subj`·`env`·`dbms`·`schema`·`ver`·`prg`·`idx`·`stat`·`reset`·`call`·`row`·`hit`·`read`·`tot`·`mean`·`live`·`dead`·`full`·`scan`·`last`·`vacuum`·`risk`·`lvl`·`tune`·`set`·`site`·`sort`·`ko`·`en`·`db`·`sql`·`ref`(`seq`·`chg`·`tbl`·`rsn` 은 기등재라 제외). `cod` 는 접두사 전용으로 두고 컬럼 토큰은 기존 `cd` 를 쓴다(`cod_set_id` → `cd_set_id`, `cod_val_*` → `cd_val_*`; `cd` 와 이음동의 회피). **약어 길이 규칙(§1-1 v2.3 자음 위주 2~3자) 위반 후보(4자 이상 전부)** `vacuum`·`schema`·`reset`·`expct`·`dbms`·`sevr`·`rule`·`mean`·`live`·`dead`·`full`·`scan`·`last`·`read`·`call`·`tune`·`risk`·`site`·`sort`·`glos`·`subj`·`clct`·`rslt`·`rcmd`·`efct`·`exec`·`stat` 은 등재 시 축약안(예 `vcm`·`scm`·`rst`·`exp`·`dbm`·`svr`·`rl`·`avg`·`lv`·`dd`·`fl`·`scn`·`lst`·`rd`·`cl`·`tn`·`rsk`·`st`·`srt`·`gls`·`sbj`·`clc`·`rst`·`rcm`·`eft`·`exc`·`sta` — `mean` → `avg` 는 축약이 아니라 대체어) 또는 관용 약어 예외를 §8-2 에서 함께 결정한다. 판정 메모 : 축약안 중 `svr`(server)·`exp`(expire)·`st`(start·status)·`dd`(day)·`lv`(`lvl` 과 병존)·`rst`(reset 과 result 충돌)는 관용 약어와 겹치므로 등재 때 다른 안을 택할 것. `rslt`·`rcmd`·`tune` 은 테이블명(`std_chk_rslt`·`prf_tune_rcmd`·`prf_tune_rslt`)에도 쓰이므로 §8-2 결정에 따라 테이블명도 함께 바뀐다. 도메인 전용 약어 `val`(`cd_val_*`)·`key`(`env_key_nm`)를 컬럼 중간 토큰으로 쓸 수 있는지도 같은 자리에서 결정. 이음동의어 금지(§1-1)에 따라 `model`(→`mdl`)·`aprv`(→기존 `apv`)·`dom`(웹 도메인 뜻)·`seq`(sequential 뜻)는 쓰지 않는다. 신규 표준도메인 `ms`(밀리초, NUMERIC) 1건. §1-3 은 미등재 단어 사용을 금지하므로 **DDL 작성 전 `std_dic`·`std_dom` 등재(P01·P02 → P20 승인)** 가 선행 작업이다. 최종 목록은 `std_dic` 실제 등재 상태와 대조해 확정 [확인중 : std_dic 조회]. `ord` 는 신규 사용 금지(§1-2 v2.3)라 `sort_seq`.

DDL 은 `sql/` 에 작성 시 da-ddl-guard 통과가 전제.

## 7. 제외 · 리스크

- **제외** : 범정부 데이터플랫폼·ITSM·전자결재 연계(공공 납품 전용), 이기종 DBMS, 그래픽 ERD 편집기(텍스트 export 로 대체), 데이터 값 프로파일링(§5 저촉), 앱의 운영 DB 직접 DDL 실행(자동 튜닝 적용).
- **리스크 1 — 접두사·단어 등재** : `mdl_`·`prf_`(또는 `metric_`)(·`biz_`)와 §4 신규 단어는 DA 승인 없이는 Hook·§1-3 규칙이 막는다. 승인과 함께 R2 목록·README §3·`std_dic` 갱신 선행.
- **리스크 2 — 19 사이트 접속(B안)** : 사이트별 Supabase 접속 정보를 메타 앱이 보유. 구조·통계 전용 role 발급 절차 [확인중 : Supabase] + §5 정책 해석 선행. A안은 해당 없음.
- **리스크 3 — 통계 누적치** : `pg_stat_statements` 는 누적 카운터라 reset·재시작 시 역전. 수집 시점마다 `stat_reset_dtm` 을 함께 저장해 증분으로 환산(P35).
- **리스크 4 — AI 권고 품질** : 실행계획 없이 쿼리 텍스트만 주면 오권고 가능. P40 입력에 P39 실행계획을 필수로 묶고, 권고는 반드시 P42 측정으로 닫는다(측정 없는 권고는 APPLIED 전이 불가).
- **리스크 5 — 운영 부하** : 수집은 카탈로그·통계 뷰 조회뿐이라 가볍지만, 전수 검사 P18 과 시계열 집계는 배치로 분리, 화면은 결과만 조회.
