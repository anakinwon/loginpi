## 2. 모델러 판정 M-1~M-17

- **M-1 승인** — 001 판정 11 번복. 사유 ①~④는 실제 소실 경로(API 코드 위치 명시)라 "선례 준수" 류 순환 사유가 아니다. 판정 11 자체가 "심사 이력 요건이 생기면 추가"를 예고했고 REQ-26·80 이 그 요건이다.
- M-2(트리거 자동 기록)·M-3(현재값 4컬럼 + CHECK)·M-4·M-5(RPC 원자화)·M-7·M-8(교차 테이블 조건 = 트리거 단일 관문)·M-9(불변식=트리거 / 판단 행위=RPC)·M-10·M-11·M-13·M-14·M-15·M-17 : **승인**.
- **M-6 승인** — REGISTER(무료·주문 없음)·EXTEND(주문 유형) 제외는 단가 이중 관리 방지로 타당. 01 §5 `fee_tp_cd` 코드값 목록은 최종 문서에서 모델 기준으로 정합 표기(01 재개정 불요).
- **M-12 승인** — 대표 이미지 단일 출처 유지.
- **M-16 / (j)#15 MBR 판정 (리더 확정)** : MBR 은 정본 §9 등재어(member)다. '멤버십'은 회원 자격이라 같은 개념 계열로 보고 **기존 MBR 재사용, 신규 등재 불요**. `fn_sel_mbr_actv_yn` 유지. (j)#15 를 "판정 완료"로 표기.
- **FK 제약명 예외 (리더 확정)** : 정본 §5 `<자식>_<부모>_id_fkey` 는 같은 부모 FK 가 2개 이상이거나 PK 가 아닌 자연키를 참조하면 구분 불가. 이 경우 `<자식>_<FK컬럼>_fkey`(예 `site_mst_vrf_usr_id_fkey`·`usr_snc_tgt_usr_id_fkey`·`fee_ord_fee_plan_cd_fkey`·`fee_ord_upr_ord_id_fkey`)를 허용한다. 정본 개정 제안 **P-6** 으로 상신.
