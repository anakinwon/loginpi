# 10_modeler_gap — 모델링·물리 설계 규칙 구→신 누락 비교 (da-modeler, 2026-10-14)

> 범위: 모델링·물리 설계 규칙. 표준단어·도메인·용어 형식(약어 길이·동음이의어 등)은 da-standards, 품질 P1~P3·점검 절차는 da-quality 소관이라 여기서는 모델·물리에 직접 닿는 항목만 다룬다.

**결론 한 줄**: 신규 04·05는 일반론(정규화·ERD·서브타입·이력)은 구보다 오히려 풍부하지만, 이 프로젝트의 **강제 규칙 계층(물리 DELETE 금지의 DDL 차단, `del_yn`+`del_dtm` 필수, `_log/_hist` 면제, `mod_dtm` 트리거, 제약조건·RLS 명명, DA-APPROVED bypass, Hook R1~R8, 접두사 23종, FK 유지·단계 전환, PostgREST 의존)은 통째로 빠졌다.** 게다가 신규의 물리 필수 표준 STD-01~08은 **Oracle 단일 기준**이라 프로젝트(Supabase PostgreSQL 네이티브)와 6개 축(FK·날짜 타입·Y/N 타입·시스템 컬럼 명칭·테이블/제약 명명·PK 채번)에서 정면 충돌한다. 누락 보완만으로는 안 되고 **"PostgreSQL 네이티브 시스템 적용 프로파일"(STD 예외 절)**을 신규 01에 두는 것이 선결이다 — §2 상충 절 참조.

## 부록 A. [M] 8.5에 그대로 붙일 PostgreSQL 표준 템플릿 (출처: README §6)

```sql
-- PostgreSQL 네이티브 신규 테이블 표준 템플릿 (출처: 구 docs/da/README.md §6, da-ddl-guard 통과 보장)
CREATE TABLE <접두사>_<엔터티약어> (
  <엔터티약어>_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  -- 업무 컬럼 (표준용어 형식: 단어1(_단어n)_도메인, 단어 2개 이상)
  del_yn  CHAR(1)     NOT NULL DEFAULT 'N' CHECK (del_yn IN ('Y', 'N')),
  del_dtm TIMESTAMPTZ,
  regr_id TEXT        NOT NULL DEFAULT 'ADMIN',
  reg_dtm TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  modr_id TEXT        NOT NULL DEFAULT 'ADMIN',
  mod_dtm TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE OR REPLACE FUNCTION fn_upd_<테이블명>_mod_dtm() RETURNS TRIGGER AS $$
BEGIN
  NEW.mod_dtm = CURRENT_TIMESTAMP;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_<테이블명>_mod_dtm
  BEFORE UPDATE ON <테이블명>
  FOR EACH ROW EXECUTE FUNCTION fn_upd_<테이블명>_mod_dtm();
```
