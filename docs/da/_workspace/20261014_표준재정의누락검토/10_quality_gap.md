- **핵심 결론 3가지**
  1. **P1/P2/P3 등급 체계가 신규에 없다.** 신규는 오류·경고 2단계(01 별표 1)뿐이며, 03에는 위반 등급·등급별 조치 기한이 전혀 없다(A51·A06).
  2. **신규 물리 규칙은 Oracle 전제라 프로젝트 정본(PostgreSQL)과 9건이 상충한다.** 특히 STD-08 "FK 제약 사용 안 함"은 CLAUDE.md FK 유지 정책(2026-07-01 PGRST200 사고)과 정면 충돌한다(§2 C2).
  3. **재발 방지 교훈 4건이 통째로 빠졌다.** ALTER ADD COLUMN 검사 사각지대(#21), 승인 주석 자가 부여 순환 논리(2026-06-12), 승계 객체 점검 제외 구멍(#22), 문서 예시가 위반을 정상 예로 제시한 원인(#22-②)이다.

판정 기준: **있음** = 같은 규칙이 같은 강도로 존재 / **부분** = 취지는 있으나 범위·강도·형식·등급 중 하나가 빠짐 / **없음** = 대응 문장 없음 / **상충** = 신규 문장이 구 규칙과 반대 또는 양립 불가.

## 4. 이 잡의 품질 게이트 기준

리더가 신규 문서 반영을 마친 뒤 다음 다섯 조건을 모두 만족하면 **PASS**, 하나라도 어기면 **FAIL**로 판정한다. 첫째, 본 비교의 '없음' 18건과 '부분' 34건은 각각 반영 문장이 신규 01~09의 제안 위치에 실제로 들어갔거나, 반영하지 않는 사유가 누락검토 보고서에 건별로 적혀 있어야 한다. 그중 P1 상당 항목(A20~A22 논리 삭제, A29 단일 단어, A30 점검 범위, A51 등급 체계, A57 ALTER ADD COLUMN)은 사유를 들어 빼는 것을 허용하지 않는다. 둘째, '상충' 9건은 신규 본문을 지우지 않고 DBMS별 적용 부칙 같은 보완 절로 해소해야 한다. C2(FK)는 "이 프로젝트에 STD-08 미적용" 문장이 없으면 다른 항목 결과와 관계없이 FAIL이다. 셋째, 추가한 모든 문장 끝에 구 출처(문서·절 또는 §10 #번호)가 병기되어야 한다. 넷째, 신규 문서의 기존 본문은 삭제·재작성되지 않아야 하고(추가만 허용), 정본 `데이터표준규칙.md`·`품질점검기준서.md`는 이번 잡에서 변경되지 않아야 한다(git diff로 확인). 다섯째, C15의 DQ 시스템 기능 탭 존재 여부를 원본 docx에서 확인한 결과가 보고서에 적혀 있어야 한다.
