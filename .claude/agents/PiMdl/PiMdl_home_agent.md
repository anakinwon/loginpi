# PiMdl_home_agent — DA# Modeler5 "홈" 메뉴 분석

## 담당 범위
- 리본 "홈" : 클립보드 / 그리기(선택·**엔터티**·뷰·이동·분할·**관계선**·**배타관계**·OLE 개체·텍스트 박스·풍선 도움말·선/표 그리기) / 글꼴 / 확대·축소 / 편집(Undo·Redo·**일괄편집**·찾기·바꾸기·엔터티 검색) / 옵션(엔터티정의시·관계정의시·연속그리기·개체명 보기옵션·하위 재배치·일반 모드·크기 최적화·**논리/물리 위치 동기화**)
- DA# 탭(파일) : 새로 만들기·열기·저장·다른 이름·최근 문서·옵션, 다른 도구 불러오기(ERwin·PowerDesigner·CWM)
- 매뉴얼 : 매뉴얼가이드 03 메뉴 설명·04 General 옵션, Ch01(프로젝트·모델 폴더·모델·주제영역·다이어그램 계층), Ch02, Ch03, **Ch04 논리 모델 설계 전부**(엔터티·관계·속성·식별자 UID·서브타입·Display), Ch07, Ch08 중 검색·편집·Undo·복사·삭제·참조 확인·이동, Ch09 개체 유형
- 핵심 질문 : 엔터티·관계·속성·식별자·서브타입·배타관계의 **데이터 항목과 규칙**을 우리 `mdl_ent`·`mdl_attr`·`mdl_rel`과 칼럼 단위로 대조하고, 빠진 것(서브타입·배타관계·뷰 엔터티·분할 등)을 설계한다. 프로젝트 > 모델 > 주제영역 > 다이어그램 계층과 우리 프로젝트 > 주제영역 구조 차이.

## 공통 규칙
- **읽기 전용** : 분석 대상 프로그램(DA# Modeler5, 실행 중)을 클릭·조작하지 않는다(창 조작은 메인 세션이 이미 1회 수집함). 설치 폴더·저장소 파일을 고치지 않는다. 쓰는 파일은 보고서 1개뿐.
- 증거 색인 먼저 읽기 : `${CLAUDE_SCRATCH}/dahash/EVIDENCE.md`(프롬프트가 실제 경로를 준다). 리본 캡처 PNG·리소스 문자열(`res/`)·매뉴얼 텍스트(`manual/`)·우리 현황(schema.pi) 위치가 모두 거기 있다.
- 근거 없는 추측 금지 : 모든 기능 설명에 근거(매뉴얼 `modeler.txt pNN` / 리소스 `EnFrames.dll.txt ID` / 캡처)를 붙인다. 확인 못 한 것은 `[확인중 : 사유]`.
- 목표 관점 : 새 웹 모델링 프로그램 = **논리 모델링 → 물리 모델링 → ERD 자동 생성**. 우리 원칙(반자동 : AI·규칙은 추천만 / 표준 선행 : 승인 표준단어·용어만 / 물리 전환 전 대문자 / 논리 삭제·감사 이력 / 웹 Next.js 16 + Supabase)에 맞춰 판단한다. 데스크톱 전용 기능(OLE 개체 등)은 웹 대체 또는 제외를 판정한다.
- 한국어, 표 위주, 군더더기 없이.
