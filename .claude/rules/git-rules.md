# Git 관리 규칙

## 커밋 메시지
- **한국어**로 작성한다.
- 형식: `<핵심 요약> — <상세 내용(선택)>` 한 줄 요약을 첫 줄에 둔다.
  (예: `PPT 템플릿 정의서에 작성 가이드 절 추가 — 5개 영역별 역할·원칙·검수 기준`)
- 요약은 **무엇을 왜** 바꿨는지 알 수 있게 쓴다. "수정", "업데이트" 단독 사용 금지.
- 여러 성격의 변경은 커밋을 분리한다 (산출물 갱신 / 도구 수정 / 설정 변경은 별개 커밋).

## 커밋 단위·대상
- 커밋 전 `git status`·`git diff`로 **변경 내용을 확인한 뒤** 스테이징한다.
  `git add .` 같은 전체 추가 대신 파일을 지정해 추가한다.
- 커밋 금지 대상:
  - 시크릿·자격증명 (API 키, 계정 정보, 접속 문자열) — 위치만 문서에 안내
  - 임시 파일·스크래치 산출물, OS 부산물(`Thumbs.db`, `~$*.pptx` 등)
  - 대용량 바이너리 중간본 — 확정본만 커밋 (버전은 파일명 `v0.NN-YYYYMMDD`로 관리)
- 산출물(pptx 등)과 이를 생성한 도구(js)는 **같은 커밋**에 묶어 추적성을 유지한다.

## 브랜치·푸시
- 기본 브랜치: `main`. 직접 커밋을 허용하되, 실험적 변경은 브랜치를 만들어 작업한다.
- 브랜치명: `<유형>/<주제>` (예: `feat/장표-4.6-암호화`, `fix/sql-시퀀스점검`).
- `main`에 **force push 금지**. 되돌릴 때는 `git revert`를 사용한다.
- 푸시 전 `git pull --rebase`로 원격과 동기화하고, 충돌은 로컬에서 해결 후 푸시한다.

## 줄 끝(EOL)·인코딩
- Windows 환경이므로 CRLF 오염에 주의한다.
- 셸 스크립트는 LF 필수: `.gitattributes`에 `*.sh text eol=lf` 지정을 원칙으로 한다.
- 텍스트 파일 인코딩은 **UTF-8** (한국어 파일명·내용 다수).

## 이력 관리
- 이미 푸시된 커밋은 amend/rebase 하지 않는다 (푸시 전 로컬 정리는 허용).
- 파일 이동·이름 변경은 내용 수정과 분리해 커밋한다 (rename 추적 유지).
- 백업 폴더(`backup_YYYYMMDD/`)로 옮기는 정리는 이동만 담은 커밋으로 별도 처리한다.
