## 2. 단계별 목적·산출·검토 포인트

### 10 프롬프트
- **목적** : 메인(아소카)의 운영 규칙(0절, 최우선 — 메인 직접 작업 금지·전문가 지명표·턴 진행 절차)과 브리프 한 건의 품질.
- **산출** : 서브에이전트 브리프(D-2 템플릿 — 목표 한 문장·쓰기 허용 경로·완료 기준 AC-n·금지 사항·출력 형식), 마스터 요청 정리(D-1).
- **검토** : 0-4절 ① 체크리스트(목표 한 문장, 범위, 실행으로 판정 가능한 완료 기준, 금지, 이미 확인한 것, 출력 형식, 정본 우선순위).

### 20 컨텍스트
- **목적** : 항상 로드되는 것은 짧게, 사라지는 것은 파일로, 오래된 맥락은 검증 후 사용.
- **산출** : 공용 컨텍스트 파일(D-1), 세션 인계 메모(D-2), CLAUDE.md 절 추가 기준(D-3).
- **검토** : 경로로 가리키기(붙여 넣지 않기), 비밀값 없음, 결론과 근거 분리, 메모리 검증, 다음 노드용 파일 지정.

### 30 하네스
- **목적** : "지시는 권고, 하네스는 강제" — "반드시" 규칙은 훅으로, 훅으로 못 만들면 40 루프에서 검증.
- **산출** : 훅(이벤트 선택·품질 기준 A-1·A-2), 권한, MCP, 에이전트·스킬 정의(D-2 frontmatter), 격리, 관측(상태줄·작업 이력·비용).
- **이 저장소의 하네스** : 훅 4종(`model-advisor`·`codex-gate`·`turn-gate`·`push-guard`) + 관측 훅(`work-history-logger`·`work-stats-refresh`·`request-graph-refresh`) + 결정적 커밋 검사(`scripts/precommit-check.mjs`).
- **Codex 와의 관계** : 하네스 파일 변경도 **루프 판정(c4)에 흡수** — 자동 계약에 AC-4(규칙 정합·우회·회귀 없음·selftest 근거)가 붙는다. 하네스 전용 판정 칸(c3)은 폐지(이력).

### 40 루프
- **목적** : 구현(서브에이전트) → Codex 판정 → 회송 → 재판정 → 승인. 상한·멈춤 조건을 이름 붙여 하나로.
- **산출** : 루프 계약(D-1, 훅이 `L/contract.md` 로 저장), `[Iteration N]` 보고(D-2), 독립 판정 표 `L/iter-N.triage.md`(D-3), 최종 보고(D-4).
- **현행** : 파일을 바꾼 에이전트가 끝나면 SubagentStop 훅이 판정 → 상세 [codex-verification.md](codex-verification.md).

### 50 그래프
- **목적** : 병렬/직렬·합류 관문·단일 작성자·재시작 가능·사람 노드를 설계(체크리스트 10).
- **산출** : 노드 카드(E-1), 엣지 계약(E-2), Workflow 골격(E-3), 그리고 **요청 흐름 그래프**(생성기 산출 HTML·md) → 상세 [graph-engineering-obsidian.md](graph-engineering-obsidian.md).

## 4. 메인의 4층 검토와의 관계

`anakins_prompt.md` 0-4절은 메인이 매 턴 **프롬프트 → 컨텍스트 → 하네스 → 그래프** 4층을 검토한다고 정한다. 40 루프는 그래프의 되돌림 엣지로 보고 그래프 층에서 함께 점검한다. 즉 "5단계"는 설계 관점의 장표 수, "4층"은 메인 검토 관점의 묶음이다.
