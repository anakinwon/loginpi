# 20. 컨텍스트 엔지니어링 규칙

> 엔지니어링 5종 중 20번 — [[anakins_prompt|10 프롬프트]] · 20 컨텍스트 · [[anakins_harnes|30 하네스]] · [[anakins_loop|40 루프]] · [[anakins_graph|50 그래프]] — 목차 [[00. index]]
> 작성 2026-11-07 Claude 초안(마스터 검토 전). 수치는 2026-11-07 실측.

**한 줄 정의** : 모델이 한 턴에 보는 토큰 **전체**를 설계하는 일 — 지시·규칙·기억·도구 목록·읽은 파일·도구 결과. 무엇을 넣고, 무엇을 빼고, 언제 넣고, 어디에 남길지를 정한다.

**원리 3가지**

1. **항상 로드되는 것은 매 턴 비용**이고 주의를 흩뜨린다 → 짧게 쓰고, 상세는 정본 문서로 링크한다.
2. **컨텍스트는 사라진다**(자동 압축·세션 종료·서브에이전트 경계) → 남아야 할 것은 파일에 둔다.
3. **오래된 맥락은 사실이 아니다**(메모리·이전 세션 요약) → 쓰기 전에 지금 상태로 검증한다.

**경계** : 지시문 한 개의 짜임은 10 프롬프트, 무엇을 강제로 주입·차단할지는 30 하네스.

### A-2. 완료 기준 체크리스트

1. **L0 다이어트** — 프로젝트 CLAUDE.md 는 300줄 이하를 권장한다(현재 366, 기준값은 [마스터 결정]). 변경 이력 표·작업 이력 장문 같은 상세는 docs 로 옮기고 CLAUDE.md 에는 1줄 링크만 둔다.
2. **L0 에 다른 프로젝트 규칙 0건.**
3. **상충 0건** — 같은 주제의 규칙은 정본 1곳에만 쓴다. 하위 문서는 "상속 + 링크"만 쓴다. CLAUDE.md 'R-P0~P6 — 하위 CLAUDE.md 에 규칙 문구 복제 금지'가 모범 사례다.
4. **다단계 작업은 시작할 때 공용 컨텍스트 파일 1개를 만든다**(D-1 형식). 모든 에이전트가 먼저 읽는다. 예 : `sitemap/schema.pi/pitel/CONTEXT.md`.
5. **도구 결과는 요약해서 들여온다.**
   - 큰 파일은 범위로 읽는다.
   - JSON 은 `node -e` 로 집계해서 본다.
   - 넓은 검색은 서브에이전트에 맡기고 결론만 받는다.
   - 에이전트 전체 기록(JSONL)은 직접 열지 않는다.
6. **대화에만 있는 결정 0건** — 결정은 결정 기록 표(D#)·리뷰 파일·상태 파일에 남긴다. 자동 압축이나 세션 종료 뒤에도 이어서 할 수 있어야 한다.
7. **메모리 위생**
   - 1사실 1파일로 쓴다.
   - 저장소에 이미 있는 내용은 넣지 않는다.
   - 새로 쓰기 전에 기존 파일을 확인한다.
   - 메모리가 가리키는 파일·플래그는 쓰기 전에 실재하는지 확인한다.

## C. 금지와 멈춤

**금지**

- 대화에만 있는 결정
- 큰 원문 덤프(로그 전체, 에이전트 기록 JSONL, 수천 줄 파일)
- 같은 규칙을 두 곳에 쓰기 — 반드시 어긋난다
- 이전 세션 요약을 사실로 쓰기 — 요약은 "HISTORICAL REFERENCE ONLY"이고, git·파일로 확인한 뒤에만 쓴다
- 비밀값을 컨텍스트로 출력하기(`.env*` 값). 접속 문자열은 변수로만 다룬다

**멈춤(정리하거나 새로 시작할 신호)**

- 같은 파일을 3번 이상 다시 읽고 있다 → 필요한 사실을 공용 컨텍스트 파일에 적는다.
- 자동 압축(설정 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=75`)이 다가온다 → 그 전에 진행 상태를 파일로 남긴다.
- 주제가 바뀐다 → 새 세션(`/clear`). 진행 중인 작업에 다른 주제를 섞지 않는다.

## D. 템플릿

### D-1. 공용 컨텍스트 파일 (다단계·다중 에이전트 작업)

```markdown
# <작업명> — 공용 컨텍스트 (모든 에이전트 필독)
> 작성일 · 지시 원문 요약 · 운영 방식(위임 모드 여부) · **소유 세션/경로**

## 0. 역할      | 역할 | 하는 일 | 쓰기 경로 |
## 1. 결정 기록 | # | 항목 | 결정 | 근거 |      ← D1, D2 … 번호 고정, 바꾸면 행 추가
## 2. 규칙 요약 (위반 = 반려)
## 3. 디렉토리·산출 계약 (파일 경로 + JSON 키)
## 4. 환경 (접속 방법 — 값 출력 금지)
## 5. 도메인 규칙
## 6. 리뷰·승인 기준
```

### D-2. 세션 인계 메모 (다음 세션·포크 세션용)

```markdown
- 현재 단계 / 다음 단계 1개
- 소유 경로 (이 세션만 쓰는 곳)
- 승인된 것 / 승인 대기
- 주의 (진행 중인 백그라운드 작업, 바뀐 정본)
```

### D-3. CLAUDE.md 에 절을 추가하는 기준

- 3줄 요약 + 정본 링크. 상세는 docs 에 쓴다.
- 사고 교훈은 "날짜 + 커밋 해시 + 1줄" 로 쓴다(예 : 0d7aa24b 처럼).
- 매 턴 필요한 규칙만 CLAUDE.md 에 둔다. 특정 폴더에만 필요하면 그 폴더의 CLAUDE.md 나 `paths:` 조건부 rule 로 둔다.
