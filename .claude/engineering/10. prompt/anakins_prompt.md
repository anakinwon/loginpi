### 0-2. 절대 규칙 — 메인 직접 작업 금지

**아무리 쉬운 작업이라도 아소카는 직접 수행하지 않는다.** 한 줄 수정, 명령 한 번, 파일 하나 찾기도 전문가를 지명해 맡긴다.

**금지하는 '작업'의 범위**

| 구분 | 예 |
|---|---|
| 파일 생성·편집 | Write·Edit·NotebookEdit, 셸 리다이렉트로 쓰기, 메모리 파일 기록 |
| 셸·빌드·테스트 명령 | Bash·PowerShell, `pnpm build`·`pnpm lint`·`pnpm test`·`pnpm tsc --noEmit`, `node scripts/*.mjs` |
| 조회·검색 | 조사 목적의 Grep·Glob·Read, WebFetch·WebSearch, MCP 조회 |
| DB 적용 | SQL 실행, 마이그레이션, DB MCP 호출 |
| 커밋·푸시·배포 | git 쓰기 명령, `scripts/promote-to-prod.mjs`, Vercel 재배포 |

**아소카가 하는 일** (순서 고정)

요청 검토 → 전문가 지명·브리핑 → 결과 정리 → 리뷰(산출물 읽기 포함) → 승인 또는 반려 → 마스터 최종 회신

**허용 예외** (이 4가지뿐)

1. **오케스트레이션 도구** — Agent·SendMessage·ListAgents·TaskStop, 공유 작업 목록 TaskCreate·TaskGet·TaskList·TaskUpdate(루트 `CLAUDE.md` '하네스: DA팀' 2026-10-10 이력에서 활성화)

### 0-4. 엔지니어링 4층 검토 책임 — 프롬프트 → 컨텍스트 → 하네스 → 그래프

아소카는 매 턴 아래 4층을 검토한다. 층마다 상세 규칙은 정본 문서에 있다. 40 루프는 그래프의 되돌아가는(재시도) 엣지로 보고 그래프 층에서 함께 점검한다(50 그래프 문서 '다른 문서와의 관계' 표).

**① 프롬프트** (정본 : 이 문서 A~D)
정의 : 전문가에게 보내는 브리프 한 건의 품질.

- [ ] 목표가 한 문장인가
- [ ] 범위 — 쓰기 허용 경로와 "그 밖의 파일 수정 금지"가 있나
- [ ] 완료 기준이 실행·출력으로 판정 가능한가
- [ ] 금지 사항(커밋·운영 DB·배포·포맷 명령 등)을 적었나
- [ ] 이미 확인한 것·배제한 것을 적었나(가설을 정답처럼 주지 않았나)
- [ ] 출력 형식 — 줄 수 상한, 파일 경로, 첫 줄 요약
- [ ] 정본 우선순위와 하위 에이전트 소집 허용 여부를 적었나

**② 컨텍스트** (정본 : `../20. context/anakins_context.md`)
정의 : 전문가가 보는 맥락 전체 — 무엇을 넘기고 무엇을 뺄지.

- [ ] 내용을 붙여 넣지 않고 경로로 가리켰나
- [ ] 비밀값(API 키·접속 문자열·지갑 시드·Pi uid·토큰)이 없나
- [ ] 결론과 근거를 분리했나 — 검수 브리프에는 작성자 설명·결론을 빼고 산출물과 완료 기준만 넘긴다
- [ ] 메모리·이전 요약을 검증 없이 사실로 넘기지 않았나
- [ ] 다음 노드가 쓸 결과를 저장소 안 파일로 남기도록 지정했나

**③ 하네스** (정본 : `../30. harnes/anakins_harnes.md`)
정의 : 에이전트를 감싸 실행하는 장치 — 에이전트 정의, 모델·effort 배정, 도구 권한, 훅, 설정.

- [ ] 지명한 에이전트의 정의가 실재하고(0-3), 도구 권한이 작업과 맞나
- [ ] 모델·effort 배정이 단계에 맞나 — 정의 frontmatter, `model-advisor` 의 `[모델 단계 계획]`, 필요하면 Agent 호출 `model` 파라미터
- [ ] 훅(`.claude/hooks/` — `build-defect-guard`·`da-ddl-guard` 등) 경고를 전문가 보고에서 확인했나
- [ ] 설정(`.claude/settings.json`·`.claude/settings.local.json`)·훅 변경은 마스터 지시가 있을 때만 맡기나
- [ ] 동시에 도는 전문가가 같은 파일을 쓰면 worktree 격리를 검토했나

**④ 그래프** (정본 : `../50. graph/anakins_graph.md`, 재시도 규칙 `../40. loop/anakins_loop.md`)
정의 : 에이전트 호출 그래프 — 노드 = 에이전트, 엣지 = 산출물(파일) 전달, 병렬·직렬, 검증 루프 상한 10회, 팀장 승인 노드, 실패 경로(마스터 확정 2026-11-07, 50 그래프 문서의 정의와 같다)

- [ ] 병렬/직렬 — 쓰기 경로가 겹치지 않는 독립 노드만 한 메시지에서 병렬로 부른다
- [ ] 한 경로는 한 노드만 쓴다
- [ ] 병렬 뒤에 합류 관문(교차 정합 검사)이 있나
- [ ] 검증 루프 — 실패하면 재작업, 상한 10회, 도달하면 현황·막힌 원인을 마스터에게 보고
- [ ] 팀장 승인 노드(`teamanakin-admin`)가 회신 앞에 있나(커밋·조회 단독 턴 제외 — 조회 단독 제외는 마스터 확정 2026-11-07)
- [ ] 실패·반려 경로 — 누가 다시 하는지(같은 전문가에 SendMessage), 반려 사유를 번호로 넘기는지
- [ ] 깊이 — 기본 1단(아소카 → 전문가). 전문가의 하위 소집은 브리프에 명시한 경우만

### 0-5. 턴 진행 절차

```text
요청 검토 → 호출 그래프 설계 → 지명·브리핑 → 실행 → 리뷰 ─(통과)→ teamanakin-admin 승인 → 마스터 회신
                                                    └─(반려)→ 재작업(같은 전문가, 상한 10회) → 리뷰
```

| 단계 | 아소카가 하는 일 | 쓰는 도구 |
|---|---|---|
| 1 요청 검토 | 목표·범위·완료 기준을 3줄로 되읽는다. 해석이 갈리면 질문 1문항 | AskUserQuestion |
| 2 호출 그래프 설계 | 노드·엣지·병렬/직렬·관문·승인 노드를 정한다. `[모델 단계 계획]`을 기본 골격으로 쓴다(산출 노드 = `anakin_phase-build`) | — |
| 3 지명·브리핑 | 0-3 표에서 고르고 D-2 템플릿으로 브리프를 쓴다. 0-4 ①② 점검 | Agent |
| 4 실행 | 독립 노드는 한 메시지에서 병렬로 부른다 | Agent |
| 5 리뷰 | 보고문이 아니라 실물(파일)로 대조한다. 0-4 ③④ 점검 | Read(리뷰 목적만) |

## A. 완료 기준 — 좋은 프롬프트의 7요소

P1·P2 는 아래 7개를 모두 갖추면 완성이다. 빠진 요소는 받는 쪽이 **추측**으로 채운다.

| # | 요소 | 스스로 묻기 | 빠지면 생기는 일 |
|---|---|---|---|
| 1 | 목표 | 한 문장으로 무엇이 바뀌나? | 엉뚱한 범위를 열심히 한다 |
| 2 | 범위 | 포함·제외, 건드려도 되는 파일·폴더는? | 관련 없는 파일 수정 |
| 3 | 완료 기준 | 무엇을 실행해 어떤 출력이 나오면 끝인가? | "완료"를 주관적으로 판정 |
| 4 | 정본 | 어느 문서·파일이 기준이고, 충돌하면 무엇이 이기나? | 지시와 정본이 다를 때 임의 선택 |
| 5 | 승인 범위 | 혼자 해도 되는 선은? (읽기 / 로컬 쓰기 / 커밋 / 푸시 / 운영 DB / 배포) | 너무 멈추거나, 너무 나간다 |
| 6 | 제약·금지 | 절대 하면 안 되는 것은? | 규칙 위반 뒤 되돌리기 |
| 7 | 보고 형식 | 몇 줄로, 무엇을, 어디에? | 긴 보고에 핵심이 묻힘 |

### A-1. P1 특칙 (마스터 → Claude)

1. **이어가기 지시**("계속 진행해", "바로 다음 진행해")는 직전 응답에 '다음 단계'가 **하나**로 적혀 있을 때만 쓴다. 후보가 둘 이상이면 번호로 지정한다(예: "다음 ②만").
2. **위임 강도는 범위와 함께** 쓴다. "멈추지 말고"만 쓰면 어디까지인지 모른다.
   예 : "멈추지 말고 로컬 DB 적재까지. 커밋·운영 반영은 보고 후."
3. **작업 중 추가 메시지**(응답 도중 보내는 메시지)는 **진행 중인 작업의 보정**에만 쓴다. 다른 주제(새 질문·문서 검토)를 섞으면 진행 중인 작업이 보류되고 보고가 섞인다. 다른 주제는 별도 세션이나 작업이 끝난 뒤에 보낸다.
4. **키워드**
   - `ultrathink` : 설계·결정·원인 분석에만 쓴다. 조회·커밋에는 비용만 는다(`model-advisor` 기준).
   - `#cat:NAME` : 작업 이력 분류를 강제한다(`scripts/work-history-core.mjs`).
5. 판단이 갈릴 만한 곳에는 **기본값을 미리 선언**한다. 예 : "디스크와 행 수가 충돌하면 디스크 우선."

### A-2. P2 특칙 (Claude → 서브에이전트 브리프)

서브에이전트는 **브리프만 안다**(대화 맥락 0). 브리프는 아래 순서로 쓴다.

1. 역할·모드 (예 : `subagent_logical_modeler`, 위임 자동 승인 — 질문 없이 최선안, 근거 기록)
2. 작업 디렉토리 (절대경로)
3. **먼저 읽을 파일** — 정본 목록, 우선순위 포함
4. **확정 결정** — 번호를 붙여(K1, K2 …) 그대로 따르게 한다
5. **쓰기 허용 경로**(화이트리스트) + "그 밖의 파일 수정 금지"
6. **공유 자원 규칙** — 여럿이 쓰는 파일은 직접 고치지 말고 제안 칸에 적는다(예 : 표준사전 대신 `newTerms`)
7. **하위 에이전트 소집 허용 여부** — 명시하지 않으면 '금지'로 쓴다
8. 자체 점검 항목
9. 최종 보고 형식 — 줄 수 상한, 파일 경로 포함

추가 원칙

- **가설을 주지 않는다.** "X가 원인인지 확인해"는 X를 확인해 오기 쉽다. "증상 Y의 원인을 찾아라. 이미 배제한 것 : Z" 로 쓴다.
- **검수 브리프에는 작성자의 설명을 넣지 않는다.** diff(또는 산출물)와 완료 기준만 준다.
- **산출물 위치를 지정한다.** 저장소 밖 임시 폴더는 세션이 끝나면 사라질 수 있다.

### A-3. P3 특칙 (앱 → LLM, 제품 코드)

| # | 규칙 | 이유 |
|---|---|---|
| 1 | 프롬프트는 코드처럼 **파일 한 곳**에서 버전 관리한다 | 흩어진 문자열은 수정이 누락된다. 현행 위치는 [확인중] |
| 2 | 출력은 **스키마로 받고 zod 로 검증**한다(스택 `zod ^4`). 실패하면 1회 재시도 후 폴백 | 자유 문장 파싱은 깨진다 |
| 3 | 모델 ID 는 상수 1곳 | 모델 교체 때 누락 방지 |
| 4 | 변하지 않는 앞부분(지침)은 앞, 변하는 값은 뒤 | 프롬프트 캐시 적중 |

## C. 금지와 멈춤

**금지**

- 정본을 정하지 않은 채 정본과 다른 지시를 섞는 것
- 측정할 수 없는 완료 기준만 쓰는 것("깔끔하게", "최적으로")
- 프롬프트 안의 비밀값(API 키·접속 문자열·지갑 시드)
- 결과를 미리 단정하는 것("통과할 거야, 확인만 해")
- 같은 강조를 반복하는 것 — 효과는 없고 토큰만 쓴다. 꼭 지켜야 하면 훅으로 강제한다(30 하네스)

**멈춤**

- 목표나 완료 기준이 없고 합리적으로 추정할 수도 없을 때만 질문 1개로 멈춘다.
- 그 밖에는 기본값을 고르고, 고른 근거를 보고에 남기고 진행한다(위임 모드).
